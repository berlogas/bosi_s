## Волна 1. P1 — корректность (2–3 дня)

### F1. SSE не должен обрываться после первой задачи — сделано

**Симптом.** Запущены две долгие задачи. Первая завершилась — вторая
перестаёт обновлять прогресс до F5.

**Причина.** Двойное закрытие:

- клиент: `eventSource.close()` при `!isActiveTask(status)`
  (`dashboard/queries.ts`);
- сервер: `break` после первой `finished` (`backend/app/api/tasks.py:78`).

**Правка.**

1. Убрать `break` из серверного генератора; поток живёт, пока клиент
   подключён, отписка — в `finally`/`CancelledError`.
2. На клиенте не закрывать `EventSource` при завершении задачи; закрытие —
   только в cleanup эффекта.
3. Подписку поднять в один провайдер (пригодится для ящика задач), иначе
   каждый вызов хука создаёт свой поток.
4. Добавить защиту от StrictMode (двойной mount в dev) и переподключение
   после разрыва.

**Приёмка.**

- Две параллельные задачи: после завершения первой вторая продолжает менять
  `progress/step` без F5.
- В сети ровно один `/api/tasks/events` на вкладку.
- После кратковременного разрыва соединение восстанавливается, пропущенные
  статусы подтягиваются из `GET /api/tasks`.
- Завершённые задачи не остаются в `activeTasks` навсегда.
- `pytest tests/test_tasks_sse.py` и `npm test` зелёные.

**Что сделано.** Подписка на задачи одна на всё приложение: `TaskEventsProvider`
живёт в `AppLayout`, поэтому в сети ровно один `/api/tasks/events` на вкладку.
`EventSource` не закрывается по статусу задачи — `close()` остался только в
cleanup эффекта (размонтирование layout, выход из аккаунта); при обрыве
браузер переподключается сам, а `onopen` инвалидирует `activeTasks`, чтобы
пропущенные статусы подтянулись из `GET /api/tasks`. Финальный статус задачи
всегда пишется в `chatKeys.task(id)` (этим гасится панель этапов в чате), а
из `activeTasks` задача уходит по предикату `isActiveTask`
(`features/dashboard/queries.ts` — единственный источник истины). На сервере
генератор `_task_event_stream` (`backend/app/api/tasks.py`) больше не делает
`break` после первой завершённой задачи: поток бесконечный, keep-alive раз в
15 с, отписка — в `finally`. Регрессия закрыта тестом «две задачи параллельно:
завершение одной не закрывает канал и не теряет вторую»
(`webapp/src/features/dashboard/dashboard.test.tsx`).

### F2. Локальное время вместо среза ISO — сделано

**Симптом.** Пользователь в UTC+3 видит время события на 3 часа раньше.

**Причина.** `shortWhen` делает `iso.slice(0, 16)` — это UTC-строка без
конвертации.

**Правка.**

- `Intl.DateTimeFormat('ru-RU', { dateStyle: 'short', timeStyle: 'short' })`
  либо явные `day/month/year/hour/minute`.
- Пустая/битая дата → `''` или `'—'` (как сейчас).
- В `title` — полная дата с зоной, чтобы можно было проверить.

**Приёмка.**

- `2026-10-20T12:00:00Z` в `Europe/Moscow` → `20.10.2026, 15:00`.
- `AdminPage`, `SessionCard`, аудит используют один форматтер.
- Тест с фиксированной `TZ` проходит в CI.

**Что сделано.** Форматирование переехало в `lib/format.ts`:
`shortWhen` (дата с временем), `dayWhen` (только день) и `fullWhen`
(полная дата с зоной — для `title`). Ad-hoc `toLocaleString` /
`toLocaleDateString` из компонентов убраны. Зона зафиксирована в двух местах:
`test.env.TZ` в `vite.config.ts` (Vitest) и `timezoneId` в
`playwright.config.ts` (Playwright — отдельный раннер, `test.env` на него не
действует).

### F3. Активный пункт сайдбара — сделано

**Симптом.** Внутри сессии пункт «Текущая сессия» серый.

**Причина.** Активность считалась равенством `location.pathname === item.to`;
`item.to = /s/:id`, а путь — `/s/:id/chat`.

**Правка.**

- Предикат: `pathname === to || pathname.startsWith(to + '/')`.
- Для `/` оставить строгое равенство, иначе «Информационная панель» будет
  активна везде.
- Нативная семантика ссылки — `NavLink component={Link}`, чтобы работали Tab,
  Enter, Ctrl-клик и «открыть в новой вкладке».

**Приёмка.**

- На всех четырёх вкладках сессии пункт активен.
- На `/knowledge` и `/admin` активны только они.
- На `/` активна только панель.
- `appLayout.test.tsx` покрывает все случаи.

**Что сделано.** Активность считает `isNavItemActive(pathname, to)` в
`AppLayout.tsx`: для `/` — строгое равенство (иначе панель горела бы везде),
для остальных путей — равенство или подпуть `to + '/'`. Пункт «Текущая
сессия» ведёт на `/s/<id>`, поэтому `/chat`, `/documents`, `/projects` и
`/notes` его подсвечивают, а «Информационная панель» на них не загорается.
Пункты меню — настоящие ссылки: `NavLink component={Link}` рендерит
`<a href>`, поэтому Tab, Enter, Ctrl-клик и «открыть в новой вкладке»
работают; предикат при этом не отдан роутеру — `NavLink` из Mantine про
маршруты не знает, поэтому `active` приходит из `isNavItemActive`, а в DOM
добавлен `aria-current="page"`. Выключенный пункт (сессии ещё не было)
ссылки не имеет: `href` нет, Tab его не ловит. Переход по пункту закрывает
мобильный drawer.

Сверх плана пункт перестал зависеть от адресной строки: путь последней
открытой сессии лежит в `sessionStorage` (`boasi.lastSessionPath`,
`features/sessions/lastSession.ts`). Иначе уход в «Информационную панель» или
«Базу знаний» гасил пункт, хотя сессия никуда не делась. Значение хранится
как `{ path, userId }`: сессия одного пользователя не предлагается другому в
той же вкладке, `logout` и `dropSession` её забывают (`authStore.ts`), битое
значение читается как отсутствующее. Пока сессию не открывали, пункт
disabled и никуда не ведёт.

Покрытие: `appLayout.test.tsx` — `/s/s-1/chat`, `/s/s-1/documents`,
`/s/s-1/projects`, `/s/s-1/notes`, `/knowledge`, `/admin`, `/`, плюс ссылочная
семантика пунктов (`href`, Tab и Enter), неактивный пункт без `href`,
запоминание сессии, выход из аккаунта и чужой `userId`; e2e
`phase2.spec.ts` — «выход в меню не гасит пункт» и «после выхода сессия не
достаётся следующему пользователю вкладки».

### F4. Удаление: один pending и подтверждение — сделано

**Симптомы.**

- При удалении одного сообщения крутились все кнопки `🗑` —
  `loading={deleteMessage.isPending}` общий.
- Удаление пары в чате и документа — один клик, без подтверждения; отмены
  нет.

**Правка.**

1. `loading={deleteMessage.isPending && deleteMessage.variables === message.id}`.
2. Подтверждение для пары «вопрос+ответ»: модалка с названием вопроса.
3. Подтверждение для документа: модалка с `document.title/docname`.
4. Пока диалог открыт, запрос не уходит; «Отмена» ничего не меняет.
5. Undo не обещать: без soft-delete на бэкенде восстановление невозможно.

**Приёмка.**

- Первый клик открывает подтверждение, сеть молчит.
- Спиннер только на целевой строке.
- «Отмена» оставляет данные, «Удалить» — удаляет и обновляет список.
- Диалог доступен с клавиатуры, фокус возвращается на инициатора.
- В архиве удаление недоступно.

**Что сделано.** `loading={deleteMessage.isPending && deleteMessage.variables === message.id}`
(`ChatTab.tsx`) — спиннер только у целевой пары, а не у всех кнопок `🗑`.
Удаление пары «вопрос+ответ» спрашивает подтверждение модалкой с текстом
вопроса, удаление документа — модалкой с `document.title/docname`. Пока
диалог открыт, запрос не уходит; «Отмена» ничего не меняет.

## Волна 2. P2 — контракты, доступность, устойчивость (2–4 дня)

### F5. Resume для paused-сессии — сделано

**Уточнение.** Paused остаётся writable (`WRITABLE_STATUSES`), а
`rag_retrieval` лениво вызывает `restore_state()`, поэтому чат не «ломается».
Дефект в другом: статус навсегда остаётся `paused`, а `client.resumeSession` —
мёртвый код; после возврата нет ни реактивации, ни явного восстановления
состояния.

**Правка.**

- `useResumeSession` → `POST /sessions/{id}/resume`.
- На карточке: `paused` → «Возобновить»; `active` → «Продолжить»;
  `archived` → действия недоступны.
- Тост с `restored_documents`; переход на вкладку из `state.tab`
  (fallback `chat`).
- Баннер на `SessionPage` при прямом заходе в paused.

**Приёмка.**

- Paused → «Возобновить» → статус `active`, тост, переход на сохранённую
  вкладку.
- Active → «Продолжить» не вызывает `resume`.
- Archived → кнопки недоступны.
- Прямой URL paused показывает баннер; после resume он исчезает.
- Ошибка остаётся видимой и не меняет статус.

**Что сделано.** `useResumeSession` вызывает `POST /sessions/{id}/resume`, так
что `client.resumeSession` больше не мёртвый код. На карточке: `paused` —
«Возобновить», `active` — «Продолжить», `archived` — действия недоступны.
После ответа тост показывает `restored_documents`, переход — на вкладку из
`state.tab` (fallback `chat`). Прямой заход в paused показывает баннер на
`SessionPage`.

### F6. Правило архивации paused — решено

API `archive_session` не запрещает paused, а UI блокировал кнопку
(`disabled={status !== 'active'}`).

**Варианты.**

- разрешить архивацию paused в UI (сохраняет смысл «убрать с глаз»);
- запретить на бэкенде и оставить запрет в UI, но добавить подсказку «сначала
  возобновите».

**Решение:** разрешить архивацию paused в UI.

**Обоснование.**

- `archive_session` не запрещает paused — поведение UI и API совпадает без
  правок бэкенда.
- Кнопка «Архив» в `SessionCard` заблокирована только для `archived`
  (`disabled={archived}`), поэтому paused уходит в архив тем же путём, что и
  active.
- Сессию можно вернуть через resume, так что архивация не тупик.

**Приёмка.**

- Paused → Архив → сессия переходит в архив (статус `archived`).
- Тест на paused покрывает сценарий архивации.
- Поведение UI и API совпадает: `archive_session` работает и для paused, и для
  active.

### F9. ErrorBoundary — сделано

Добавить `RouteErrorBoundary` вокруг layout/route-элементов: заголовок
«Что-то сломалось», текст ошибки, кнопки «Обновить» и «На панель».

раздел. Внутри `AppLayout` тем же компонентом обёрнут `Outlet`, так что падение
страницы не уносит сайдбар.

`navbar={{ collapsed: { mobile: false } }}` — сайдбар всегда занимал 260px.

**Правка:** `mobile: true`, `Burger` в шапке, закрытие drawer при переходе,

### F11. Тёмная тема — сделано

Сейчас `MantineProvider defaultColorScheme="light"` и хардкоды `gray.0`,
`yellow.2`, `blue-4`, `blue-light`, `blue-6`. Чек-лист п. 8.3 требует тёмную

**Приёмка:** переключение без F5-вспышки; читаемость всех перечисленных мест;
скриншоты light/dark.

**Что сделано.** Схема управляется через `MantineProvider` с
`defaultColorScheme="auto"` и `localStorageColorSchemeManager` (ключ
`mantine-color-scheme-value`). Выбор применяется до первого кадра: inline-скрипт
в `index.html` читает сохранённое значение (или `prefers-color-scheme`) и ставит
`data-mantine-color-scheme` на `<html>` — после F5 страница не вспыхивает

(`gray.0` → `--mantine-color-gray-light`), подсветка активного источника
(`yellow.2` → `--mantine-color-yellow-light`), рамка и подложка dropzone
(`blue-4` → `--mantine-color-blue-filled`, `blue-light` остался — переменная
сама темнеет в dark), полоса прогресса (`blue-6` → `--mantine-color-blue-filled`).

Покрытие: `appLayout.test.tsx` — по умолчанию «Системная», «Тёмная» пишет
`localStorage` и ставит `data-mantine-color-scheme="dark"`, возврат на
«Светлую»; e2e-пробник — переключение, `localStorage` после F5, атрибут на

1. **F1–F4** — первыми: F1 нужен для будущего ящика задач, F4 — до

3. **F10–F11** — только после решения по мобильной версии и тёмной теме;
