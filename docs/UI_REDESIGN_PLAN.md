# План улучшения интерфейса boasi_s

Дата: 2026-10-23 (редакция 2)
Объект: `webapp/src` (React + Mantine, замена Streamlit-клиента)
Ограничение: план описывает дизайн и приёмочные критерии; реализация — отдельными задачами.

---

## 1. Цель и смена оптики

Привести интерфейс к современному виду: единый дизайн-слой, понятная навигация,
мобильная и тёмная тема, снижение потери контекста при переключении страниц,
доступность с клавиатуры.

Главное изменение редакции 2: **уходим от «паритета со Streamlit» к
task-oriented UX**. Паритет был правильной стратегией миграции, но он тянет в
интерфейс лишние элементы и порядок блоков, которые нужны были Streamlit, а не
пользователю. Дальше оцениваем экраны по задачам: «быстро спросить», «найти
документ», «довести раздел статьи», «понять, что происходит с фоновой задачей».

Сохраняем сильные места: маршруты вкладок сессии, автосохранение, двухшаговые
подтверждения, панель этапов задач, санитизацию markdown, кликабельные цитаты.

## 2. Что уже сделано — не ломать

- Переключатель темы (светлая / системная / тёмная) + скрипт в `index.html` без вспышки при F5.
- `AppShell` с сайдбаром 260 px; мобильный `Burger`; сайдбар сворачивается на узком экране.
- Вкладки сессии как маршруты (`/s/:id/chat`, `documents`, `notes`, `projects`) с автосохранением активной вкладки.
- Вкладки админки в URL (`/admin/:tab`) — F5 сохраняет вкладку.
- Чат: пузыри, аватары, панель этапов с секундомером, кликабельные цитаты `[n]`, отмена задач, `base_empty`.
- Архив, очистка чата и удаление пары/документа — в два шага с модалкой.
- Один `EventSource` на приложение (`TaskEventsProvider`), SSE не закрывается после первой задачи.
- Поиск в базе знаний — с debounce, категория применяется сразу.
- Санитизация markdown, локальная зона дат через `Intl.DateTimeFormat`.
- Волна 1 (частично): эмодзи заменены на `@tabler/icons-react`; созданы `PageHeader`, `StatusBadge`, `SkeletonList`; пустые состояния частично получили действия.

## 4. Принципы дизайна

1. **Одна тема для всех.** Цвета, радиусы, тени — через `createTheme` Mantine и
   семантические токены (`success`, `warning`, `error`, `info`), не хардкод в
   компонентах. Пары light/dark — через `virtualColor`.
2. **Иконки вместо эмодзи.** `@tabler/icons-react` в кнопках и навигации;
   эмодзи только как декоративные акценты. Иконки статусов — компонент
   `StatusIcon`, а не значение в модуле форматирования.
3. **Контент поверх шума.** Один `PageHeader` на страницу; дублирующие
   `Title`/`Text` убираем. Хлебные крошки — только там, где есть реальная
   иерархия (страница сессии), а не на каждом экране.
4. **Никакой потерянной прогресс.** Фоновые задачи видны из любой страницы:
   тонкая шапка с индикатором задач и ящиком, а не только дашборд/чат.
5. **Навигация с клавиатуры.** Command palette (`Ctrl/Cmd+K`) как основной
   способ перейти в раздел, сессию или действие; Tab/Enter — везде.
6. **URL — источник истины для состояния экрана.** Вкладки, фильтры,
   сортировка, страница таблицы живут в адресе: ссылки shareable, F5 ничего
   не сбрасывает.
7. **Обратимые действия — оптимистично и с undo.** Модалка подтверждения —
   только для необратимого (архив сессии, удаление пользователя).
8. **Мобильный-first.** Сайдбар сворачивается, таблицы скроллятся по
   горизонтали, композитор чата закреплён снизу.
9. **Доступность по умолчанию.** Видимый focus-ring, ARIA, контраст WCAG AA,
   `aria-live` для фоновых задач и новых сообщений, `prefers-reduced-motion`.
10. **Производительность как критерий.** Route-level code splitting, бюджет
    бандла, `content-visibility` для длинных списков, виртуализация только там,
    где она действительно нужна.

## 5. Волны реализации

### Волна 2. Каркас (3–4 дня)

**Цель.** Единый визуальный слой и глобальная навигация; задачи видны из любой
страницы.

**Зависимости.** Ревизия Волны 1.

**Шаги**

1. **`theme.ts` + `createTheme`.** Семантические цвета, `primaryShade`,
   `defaultRadius`, `components` defaults (Button, Card, Table, Tabs, Badge).
   Пары light/dark — `virtualColor`; кастомные поверхности — CSS `light-dark()`.
   Подключить в `AppProviders`.
2. **Тонкая шапка на desktop (48 px).** Сейчас `header.height = 0` на desktop,
   поэтому глобальному ящику задач негде жить. В шапке: триггер палитры,
   индикатор задач, меню пользователя. На мобильном — `Burger` + те же элементы.
3. **Command palette (`@mantine/spotlight`).** `Ctrl/Cmd+K`: разделы, последние
   сессии, действия («Новый вопрос», «Загрузить документ», «Открыть админку»).
   Заменяет дропдаун сессий и большую часть хлебных крошек.
4. **Глобальный ящик задач.** `Indicator` + `Popover`/`Drawer`, список
   последних 3–5 задач, отмена из любой страницы. `notifications.update` для
   прогресса; `BroadcastChannel` — синхронизация между вкладками.
5. **Хлебные крошки только на странице сессии.** `Панель / Сессия / Чат` —
   там, где иерархия действительно есть.
6. **Мобильная раскладка.** `navbar.collapsed.mobile = true`, `Burger` в шапке,
   «Состояние системы» в поповере, горизонтальный скролл таблиц.
7. **URL state для фильтров/сортировки/страницы.** `useSearchParams` (или
   `nuqs` с адаптером React Router) — единый подход для таблиц и списков.

**Критерии приёмки**

- `theme.ts` подключён; в компонентах нет хардкода цветов, кроме декоративных.
- `Ctrl/Cmd+K` открывает палитру; переход в сессию и раздел работает.
- Счётчик задач виден с любой страницы; отмена из шапки меняет статус.
- Хлебные крошки есть на странице сессии и не дублируются на других экранах.
- Сайдбар сворачивается на мобильных, таблицы скроллятся по горизонтали.
- Фильтры/сортировка/страница таблицы переживают F5 и копируются ссылкой.

### Волна 3. Чат (2–3 дня)

**Цель.** Комфортная работа с длинной историей, меньше кликов, честная оценка
времени ожидания.

**Зависимости.** Волна 2 (шапка, уведомления, базовые компоненты).

**Шаги**

1. **Закреплённый композитор.** `position: sticky; bottom: 0` внутри
   scroll-контейнера + `scroll-padding-bottom`; не `fixed`, чтобы не
   перекрывать сайдбар и мобильный контент.
2. **Многострочный ввод.** `Textarea` с `autosize`; Enter — отправить,
   Shift+Enter — перенос строки.
3. **Режим поиска в композиторе.** `SegmentedControl` с иконками или компактное
   меню; фоновый режим — настройка с подсказкой, а не постоянный `Switch`.
4. **Виртуализация истории — `react-virtuoso` / `@virtuoso.dev/message-list`.**
   `@tanstack/react-virtual` требует ручной работы с variable-height,
   reverse-scroll и якорями; для чата Virtuoso решает это из коробки.
   Альтернатива без зависимости — CSS `content-visibility: auto` +
   `contain-intrinsic-size`.
5. **Кнопка «вниз» и индикатор непрочитанного.** При скролле вверх — счётчик
   новых сообщений, при возврате — сброс.
6. **Оценка времени.** Показывать `stage`/`progress`/`seconds` из задачи и
   «этап N из M». «Обычно 2–4 мин» — агрегат на бэкенде или в `localStorage`,
   а не медиана по неполной клиентской истории.
7. **Undo вместо модалки для удаления пары.** TanStack Query `onMutate` +
   `notifications.show({ action: { label: 'Отменить' } })`. Модалка остаётся
   для архива сессии.
8. **A11y.** `role="log"`, `aria-live="polite"` для новых сообщений,
   `aria-busy` на панели задач, `prefers-reduced-motion` для автоскролла.
9. **Стриминг ответа — только после backend-задачи.** Сейчас
   `PaperQA2.aquery` возвращает готовый ответ, SSE есть только для задач.
   Стриминг этапов уже работает; токен-стриминг — отдельная задача (см. §6).

**Критерии приёмки**

- Композитор закреплён снизу, `Textarea` autosize, Enter/Shift+Enter работают.
- При 100+ сообщениях нет скачков layout и потери позиции скролла.
- Удаление пары обратимо через тост; модалка не нужна.
- Новые сообщения анонсируются screen reader'ом.

### Волна 4. Документы и проекты (3–5 дней)

**Цель.** Понятные списки документов, master-detail для проектов, защита от
потери несохранённых правок.

**Зависимости.** Волна 2 (каркас, уведомления).

**Шаги — Документы**

1. **`@mantine/dropzone`** вместо самодельной dropzone: `accept`, `maxSize`,
   `onReject`, состояния загрузки и доступность из коробки.
2. **`TagsInput`** вместо `TextInput` через запятую; категория — бейджи/сегменты.
3. **Выбранные файлы — списком** с удалением по одному, размером и прогрессом.
4. **Построчные ошибки загрузки**: имя файла и причина, не только «Добавлено: N,
   ошибок: M».
5. **Таблица вместо аккордеона при большом числе документов.** Порог — ~20
   документов; ниже аккордеон остаётся. `@tanstack/react-table` (headless) +
   Mantine `Table` + `Table.ScrollContainer`; сортировка/фильтры/пагинация на
   сервере, состояние в URL.
6. **Detail panel — `Drawer` справа**, а не раскрытие строки: таблица остаётся
   сканируемой, детали не ломают layout.
7. **Удаление документа — undo-тост** (оптимистично), модалка — только если
   бэкенд не позволяет откат.

**Шаги — Проекты**

8. **Master-detail.** Список проектов слева (sticky), редактор справа; на
   мобильном — `SegmentedControl`/`Drawer`. Без новой зависимости: CSS Grid.
9. **`HowToPanel` свёрнут** в `Accordion`/popover; развёрнут только при пустом
   списке.
10. **Редактор разделов — CodeMirror 6** (`@codemirror/lang-markdown`) вместо
    raw `<textarea>`; preview — существующий `MarkdownText`.
11. **Автосейв с debounce + `useBlocker`.** `beforeunload` покрывает только
    закрытие вкладки; `useBlocker` — переходы внутри SPA. Индикатор
    «Сохраняю…» / «Сохранено».
12. **Версии и diff.** API уже готов (`/versions`, `/versions/diff`); `diff`
    (jsdiff) + компактный unified-рендер. `@git-diff-view/react` — если нужна
    подсветка/split-view.
13. **Фоновая генерация раздела.** Требует backend task API (см. §6); до этого
    оставить синхронно с честным прогрессом.
14. **Статус проекта — сохранение по изменению.** Optimistic mutation +
    debounce, без кнопки «Обновить».
15. **«Разбор черновика» — структурный список** с severity-бейджами и
    переходом к разделу, не markdown в `Alert`.

**Критерии приёмки**

- Dropzone принимает только разрешённые форматы и показывает причину отказа.
- При >20 документах таблица сортируется/фильтруется, состояние в URL.
- У раздела после генерации кнопка «История (N)»; diff показывает `+`/`-`.
- Индикатор несохранённых правок появляется при изменении черновика; уход со
  страницы предупреждает.

**Цель.** Админка как отдельные страницы, удобные таблицы, deep link на вкладки.

**Зависимости.** Волна 2.

**Шаги**

   статус в документации.
2. **Разбить `AdminPage`** (~1737 строк) на страницы/компоненты по вкладкам;

## 8. Критерии приёмки (сводные)
