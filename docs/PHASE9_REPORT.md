## Hardening: что закрыто

### Валидация путей — дыра была реальной

ТЗ требует «нет выхода за пределы каталога сессии», а эндпоинты принимали
**любой абсолютный путь**. Исследователь мог указать что угодно.

Теперь (`app/core/safety.py`):

* путь разворачивается через `resolve()` — `..` и симлинки не обходят проверку;
* результат обязан лежать в одном из корней: каталог сессии, общий каталог
  документов или каталог данных (для админа);
* симлинк, нацеленный наружу, отклоняется (проверка повторяется ПОСЛЕ resolve);
* файл вне `data_dir` остаётся недоступным даже с
  `ALLOW_EXTERNAL_IMPORT_PATHS=true` — флаг расширяет до каталога данных, но не
  за его пределы;
* отсутствующий файл в разрешённом каталоге — **404**, а не 403: «не найдено»
  и «запрещено» — разные вещи, исходный контракт API сохранён.

### Rate-limit на логин

Скользящее окно в памяти процесса: считаются **только неудачные** попытки по
паре (логин, IP), иначе медленный, но честный пользователь попал бы под
блокировку. Превышение → 429 с `retry_after_seconds`. Успешный вход сбрасывает
счётчик.

Почему в памяти, а не в БД: счётчики живут минутами, при рестарте окно должно
обнуляться, а лишняя запись на каждый неудачный логин ничего не даёт.

### SECRET_KEY

`validate_runtime()` при старте: ключ короче 32 символов или оставленный
шаблонным из `.env.example` — приложение **не стартует**. Для prod
дополнительно предупреждения: `DEBUG=true`, `MULTIMODAL=true`,
`OFFLINE_MODE=false`.

### Метрики

`GET /api/metrics` — текстовый формат Prometheus без новых зависимостей:
сессии по статусам, документы и чанки, сообщения, версии статей, задачи,
гистограмма длительности фоновых задач, uptime. `GET /api/metrics.json` —
тот же срез глазами.

## Что НЕ проверено

**Docker-демон в этой среде недоступен**, поэтому сквозной DoD фазы
(«`docker compose up` с нуля → работающая система; восстановление из бэкапа;
две-три сессии подряд») я подтвердить не мог. Проверено статически:

* `docker compose config` валиден для dev и prod-оверрайда;
* синтаксис bash-скриптов через `bash -n`;
* логика чтения моделей из `.env` и фильтрации — исполнена вручную;
* документирован порядок запуска и процедура проверки бэкапа.

Проверить на машине с Docker:

```bash
make pull-models && make up && make health
make backup && make down && make restore ARCHIVE=... && make up && make health
```

## Ограничения

* Реестр задач, «аренды» сессий и rate-limit живут в памяти процесса: одна
  реплика backend, как и задумано по ТЗ (локальный однопользовательский контур).
* SQLite + WAL рассчитан на один процесс записи.
* Модель эмбеддингов качается из HuggingFace при первом старте; для полностью
  оффлайн-контура нужен `make warm-embedding`.
* В UI нет удаления пользователя и управления чужими сессиями — намеренно,
  чтобы админ не мог спутать чужую работу (см. ADMIN_GUIDE).
