# Производительность PaperQA2

Замеры производительности boasi_s с PaperQA2 на dev-машине (8 CPU, без GPU, локальная Ollama на CPU).

## Среда тестирования

- **LLM:** Ollama `qwen2.5:3b` на CPU
- **Эмбеддинги:** `st-multi-qa-MiniLM-L6-cos-v1` (локально, sentence-transformers)
- **Режим:** `OFFLINE_MODE=true`, без интернета
- **Корпус:** 9 документов, 7 тестовых вопросов (замер 2026-10-12)

## Время ответа по режимам

| Режим | EVIDENCE_SKIP_SUMMARY | EVIDENCE_K | MAX_CONCURRENT_REQUESTS | Время ответа |
|-------|----------------------|------------|------------------------|--------------|
| Отладочный (облачная LLM) | `false` | 5 | 4 | 65–190 с |
| Быстрый итерации | `true` | 5 | 4 | ~25 с |
| Бой (Ollama на GPU) | `false` | 10 | 8 | 15–25 с (ожидается) |

> `EVIDENCE_SKIP_SUMMARY=true` отключает суммаризацию фрагментов — релевантность считается только по косинусу. Существенно быстрее, но сырой текст в контексте увеличивает prefill.

## Замер SPICE_REPORT

Ответ с суммаризацией (`evidence_skip_summary=false`): **817 с** на одном из тестовых вопросов (SPICE_REPORT §7).

## Кэш эмбеддингов

Модель эмбеддингов кэшируется через `lru_cache(maxsize=8)` в `_cached_embedding_model()`. Без кэша модель загружается с диска на каждый вызов `Settings.get_embedding_model()` — замер 2026-10-12 показал 12 лишних загрузок на один запрос.

Метрика `embedding_model_load_count()` считает реальные загрузки с диска (промахи кэша).

## Рекомендации

1. Для Ollama на CPU оставляйте `MAX_CONCURRENT_REQUESTS=1` — Ollama обрабатывает запросы последовательно, параллелизм упирается в очередь.
2. Для быстрых итераций включайте `EVIDENCE_SKIP_SUMMARY=true` (~25 с против 65–190 с).
3. Смена модели эмбеддингов требует полной переиндексации — эмбеддинги старой модели несовместимы.
4. При смене любых настроек PaperQA (модель LLM, чанк, порог релевантности) меняется `settings_fingerprint`, старые чанки требуют переиндексации.
