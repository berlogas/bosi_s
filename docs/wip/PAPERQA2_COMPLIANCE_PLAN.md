### 🎯 Таблица сценариев: когда базовый RAG, когда агент

| Задача | Режим | Почему |
|--------|-------|--------|
| Быстрый ответ на простой вопрос («Что сказано в документе X про Y?») | **Базовый RAG** (`Docs.aquery`) | Один поиск, один ответ, быстро (секунды даже на GPU) |
| Сложный вопрос, требующий синтеза из нескольких документов | **Агент** (`agent_query`) | Итеративный поиск: нашёл чанки → уточнил запрос → нашёл ещё → ответил |
| Первый поиск дал нерелевантные результаты | **Агент** | Самокоррекция: агент пробует другой запрос вместо ответа «по мусору» |
| Нужен ответ с гарантией, что все доказательства учтены | **Агент** | Агент оценивает достаточность доказательств и может refuséть, если их мало |
| Интерактивный чат, пользователь ждёт ответа быстро | **Базовый RAG** | Агент делает несколько вызовов LLM — медленнее, хотя на GPU терпимо |

**Где выбирается:** в веб-интерфейсе boasi_s (переключатель в окне чата).  
**По умолчанию:** базовый RAG. Агент включается пользователем осознанно для сложных задач.
