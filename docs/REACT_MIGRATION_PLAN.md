# План перехода интерфейса с Streamlit на React (TypeScript)

**Статус: утверждён 2026-10-06** (все решения по разделу 8 приняты по
рекомендациям автора; старт переделки — на следующий день).

Бэкенд (FastAPI) **не трогаем**: API стабильное, покрыто тестами, и весь
новый интерфейс будет работать по той же шине `/api/*`, что и сегодняшний
Streamlit.

---

## 1. Зачем и не-зачем

**Цели**
- Полноценный SPA: нет перерисовки всей страницы на каждое действие
  (у Streamlit каждый клик — сессия перезапускается);
- единый типобезопасный контракт: типы TS генерируются из
  `/api/openapi.json` — опечатки и рассинхрон поля ловятся на сборке;
- живой прогресс: вместо поллинга каждые 2 с — подписка на события
  задачи (SSE) и мгновенный рендер этапов/секундомера;
- кликабельные цитаты `[n]`: ссылка из ответа скроллит/подсвечивает
  источник в списке (сейчас это две несвязанных вещи);
- upload с реальным прогрессом (XHR progress), drag&drop из коробки;
- нормальный роутинг, клавиатура, мобильная раскладка, темы.

**Не-цели**
- никакого SSR/Next.js (приложение — приватная локальная станция);
- никакой переписки бэкенда: FastAPI, alembic, тесты, eval-скрипты
  остаются как есть;
- никакого «server-driven UI» в духе Streamlit — состояние на клиенте,
  сервер — только REST (+ опционально SSE).

**Отправная точка**
- текущий фронт: ~2200 строк Python (`frontend/`), поверх REST API;
- интерфейс декларативный и хорошо изолированный: `boasi_ui/pages/*`
  (login, dashboard, workspace, admin, project_editor), `components/ui.py`
  (task_panel, source_list, checks_view, answer_view, messages_view),
  `api.py` (клиент с refresh-токенами), `state.py` (session_state);
- AppTest-тесты (`backend/tests/test_frontend.py`, ~50) — их функционально
  заменяют Vitest+RTL и Playwright (см. раздел 6).

## 2. Целевой стек

| Слой | Выбор | Чем заменяет / зачем | Альтернативы |
|---|---|---|---|
| Билд | Vite + React 19 + TS strict | dev-сервер, HMR, сборка | — |
| Роутинг | React Router v7 | вкладки/страницы, охрана по ролям | TanStack Router |
| Серверное состояние | TanStack Query | кэш, поллинг задач (`refetchInterval`), инвалидация истории | SWR |
| Клиентское состояние | Zustand | auth (токены, user), выбранная сессия/проект | Redux Toolkit |
| UI-кит | **Mantine** | modals (подтверждение архива!), Dropzone (upload), таблицы (аудит), notifications, готовый RU-локал | shadcn/ui+Tailwind (больше ручной работы), AntD (тяжелее) |
| Типы API | openapi-typescript → `src/api/schema.ts` | типы из `/api/openapi.json`, проверка «типы актуальны» в CI | orval (типы + хуки) |
| Markdown | react-markdown + rehype-sanitize + кастомный рендер `[n]` | ответы LLM — рендер **безопасный** (XSS) | no — sanitize обязателен |
| Тесты | Vitest + React Testing Library; Playwright e2e | замена AppTest; критичные сценарии в браузере | — |
| Линт/формат | ESLint (typescript-eslint) + Prettier | как `make lint` для Python | — |

Рекомендация — **Mantine**: этому проекту нужны именно его готовые детали
(модалка подтверждения архива, drag&drop загрузки, таблицы с сортировкой,
нотификации ошибок задач), а не low-level Tailwind.

## 3. Структура репозитория

```
boasi_s/
  backend/            # БЕЗ ИЗМЕНЕНИЙ (FastAPI + тесты + eval)
  frontend/           # Streamlit — LEGACY, живёт до паритета, потом удаляется
  webapp/             # НОВЫЙ React-интерфейс
    src/
      api/            # клиент (fetch-обёртка) + schema.ts (codegen)
      features/
        auth/    sessions/   chat/    documents/
        projects/ admin/      layout/
      components/     # общие: Citations, TaskPanel, SourceList ...
      routes.tsx
    vitest/ playwright/  public/
```

Почему `webapp/`, а не переименование `frontend/ → frontend-streamlit`:
переименование сломает `scripts/start.bat/start.sh` и PID-файлы `.run/`
на всё время перехода. Streamlit остаётся продакшеном до switch-over.

Prod-раздача: FastAPI монтирует `webapp/dist` (`StaticFiles` за
`/api/*`) — один порт, ноль CORS, никакого nginx. Dev: Vite-прокси
`/api → http://localhost:8000` — CORS не нужен вовсе (существующий
`cors_origins` в `.env` менять не обязательно; добавить origin Vite
можно при желании).

## 4. Контракт API — что уже есть и чего не хватает

`/api/openapi.json` доступен с Swagger `/api/docs`. Покрытие фич:

| Фича | Эндпоинты | Готово для TS? |
|---|---|---|
| Auth | login, refresh (ротация), logout, me | ✅ |
| Сессии | список, создание, архив (2 шага — UI), деталь, состояние | ✅ |
| Чат | `POST /chat/query` (async task), `GET /chat/messages`, `GET/chat/suggest-queries` | ✅ |
| Задачи | `GET /tasks/{id}`, `GET /tasks`, `POST /tasks/{id}/cancel` | ✅ (поллинг) |
| Документы | upload, список, удаление, категории/лимиты | ✅ |
| Проекты | CRUD, связи документов | ✅ |
| Админка | users, audit, массовая индексация | ✅ |
| Состояние | `PUT /sessions/{id}/state` (точка возврата) | ✅ |

**Доработки бэкенда (минимальные, заточенные под интерфейс)**
1. `GET /api/tasks/{id}/events` — SSE: этапы прогресса вместо поллинга
   (фаза 2; до неё работаем поллингом, как сейчас — паритет уже достижим);
2. опционально: `Content-Disposition`/URL для скачивания оригиналов;
3. маленький эндпоинт `/api/meta` (версия сборки, лимиты) или отдавать
   через существующий `/health`.

## 5. Ключевые технические решения

**A. Клиент API и токены (аналог `frontend/boasi_ui/api.py`)**
- fetch-обёртка: при 401 — один общий refresh (очередь параллельных
  запросов ждут один refresh), повтор оригинального запроса, при провале
  — logout + переход на login;
- access-токен в памяти, refresh — в `localStorage` (первые 30 минут
  сессии переживают обновление вкладки; в сомнительных случаях — только
  память, как сейчас);
- все ошибки приводятся к единому `ApiError` с русским текстом и `meta`
  (лимиты!) — повторяем поведение `ApiClient._request`.

**B. Задачи и прогресс**
- Фаза 1: TanStack Query `refetchInterval: 2000` на `task(taskId)` —
  1-в-1, как сейчас;
- Фаза 2: SSE-канал; UI тот же `TaskPanel`, но обновление мгновенное;
- `task_id` в `sessionStorage`, чтобы по F5 панель восстанавливалась
  (у Streamlit это было в `session_state`).

**C. Маркдаун ответов — безопасность**
- ответ содержит произвольный текст LLM: только `react-markdown` +
  `rehype-sanitize` (CSP на старте фазы 2);
- `[n]`-цитаты рендерятся отдельным компонентом: клик → подсветка
  источника в списке; блокам `References` — тот же приём, что в
  `citation_guard` (без двоеточия) — плюс регрессионный тест на рендер.

**D. Upload**
- Mantine `Dropzone` + XHR (есть `upload.onprogress`): совместимость с
  существующим «добавление по пути» в рамках лимитов/категорий;
- повторное использование списка ошибок/лимитов из `ApiError.meta`.

**E. Состояние и снапшоты**
- табы workspace = маршруты (`/s/:id/chat`, `/s/:id/documents`…),
  автосохранение активного таба в `save_state` — как сейчас строка 557
  `workspace.py`.

## 6. Паритет-чеклист (Streamlit → React) и этапы

Каждый этап заканчивается: **порогом приёмки** (запускается
Playwright-сценарий + ручной чек-лист) и коммитом. Streamlit остаётся
включённым до последней фазы.

### Фаза 0 — каркас (2–3 дня)
- `webapp/`: Vite + TS strict + ESLint/Prettier + CI (lint, typecheck, vitest, build);
- `openapi-typescript` codegen + проверка «типы не устарели» в CI (`npm run codegen --check`);
- fetch-клиент с refresh-очередью, `ApiError`, роутинг, layout с боковой
  панелью и меткой сборки (аналог side-панели Streamlit);
- **приёмка**: пустой дашборд после логина через новую обёртку.

### Фаза 1 — авторизация и дашборд (3–4 дня)
- login (включая экран восстановления пароля), logout, `me`;
- сессии: список, создание, карточка, **архив в два шага** (модалка
  «Подтвердите: сессия уйдёт в архив»), просмотр «только чтение»;
- активные задачи на дашборде (карточки, поллинг);
- быстрый чат на дашборде (упрощённый `answer_view`);
- **приёмка**: e2e «создать сессию → заархивировать с подтверждением».

### Фаза 2 — чат, ядро (6–8 дней)
- пузыри (вопрос/ответ), удаление пары, pending-вопрос при отправке;
- `TaskPanel`: этапы (35/55/85…), секундомер, проценты, «Отменить»,
  сохранение `task_id` при F5, **ошибка/отмена задачи в чате** + удаление
  «зависшего» обмена;
- `SourceList` (📚/📁 `[n]`, категория, score), `ChecksView` (warnings из
  `stats`/`checks`), «Ответ из кэша», expander References;
- markdown-рендер с санитизацией и кликабельными `[n]`; уточняющие
  вопросы (`suggest-queries`) чипами;
- история: пагинация/виртуализация; вкладка «Заметки и точка возврата»
  (`save_state`, restore);
- **приёмка**: e2e сценарии «долгий вопрос: панель этапов → отмена»,
  «ответ с предупреждением grounding», «References отображаются»,
  «восстановление после F5».

### Фаза 3 — документы и проекты (4–6 дней)
- документы: Dropzone (drag&drop), «добавить по пути», лимиты/категории,
  список с прогрессом индексации (задачи), удаление;
- проект-редактор (перенос `project_editor.py`): CRUD, связи с
  документами, режим фокуса;
- **приёмка**: e2e-сценарий загрузки + индексации.

### Фаза 4 — админка и полировка (3–5 дней)
- пользователи (роли), аудит-таблица (сортировка/пагинация), массовая
  индексация, вкладка документов админа;
- пустые состояния, русские тексты 1-в-1, a11y, мобильная раскладка,
  тёмная тема (необязательно), `React.Suspense` для всех страниц;
- **приёмка**: регрессия полного ручного чек-листа (файл рядом с
  `USER_GUIDE.md`).

### Фаза 5 — переключение и удаление Streamlit (3–5 дней)
- дублирующая эксплуатация 1–2 недели (один день в неделю — реальные
  запросы пользователя; фиксация отличий);
- Playwright-сьют из 8 критичных сценариев зелёный;
- удаление `frontend/`, AppTest-тестов, `.streamlit`; `start.bat/start.sh`
  → запуск `uvicorn + npm run dev` (dev) / `StaticFiles` (prod); очистка
  `cors_origins`; обновление `USER_GUIDE.md` и `PHASE*_REPORT`;
- большой коммит «Streamlit удалён».

**Итого: ~21–31 рабочих дня** на одного разработчика
(≈ 4,5–6 недель full-time; при работе по вечерам — 2–3 месяца).
Кое-что сжимается: UI-часть лёгкая, самый крупный риск — чат (J6–8),
за ним админка-таблицы.

## 7. Риски и меры

| Риск | Мера |
|---|---|
| Токены: гонки 401 при истечении | единая очередь refresh на клиенте + тест с подменой времени |
| XSS через ответ LLM | sanitize + CSP + тест на «сырой HTML из ответа» |
| Потерянная функциональность без тестов | Playwright с самой первой фазы, не «в конце»; чек-лист из USER_GUIDE |
| Отличия рендера markdown (Streamlit/markdown-it vs react-markdown) | регрессионные тесты именно на странные блоки (References, `[n]`, скобки) |
| Поллинг в фоне/вкладка закрыта | поллинг только активной вкладки; SSE в фазе 2; task_id в sessionStorage |
| «Скрытые» функции Streamlit, которых нет в задачах | инвентаризация UI (раздел 6) — каждый экран назван и имеет владельца-тест |
| CORS/deploy | prod через StaticFiles на том же origin; Vite-прокси в dev |
| Windows-сценарии | npm-команды добавляются в `start.bat`/`start.sh` рядом с uvicorn |

## 8. Зафиксированные решения (утверждено 2026-10-06)

1. **UI-кит**: Mantine (модалки, Dropzone, таблицы, RU-локал);
2. **Роутинг**: React Router v7;
3. **SSE для задач**: добавляем в фазе 2 (до неё — поллинг, как сейчас;
   на старте изменений бэкенда не требуется);
4. **Раздача**: FastAPI StaticFiles (`webapp/dist` за `/api/*`, один порт,
   ноль CORS); dev — Vite-прокси `/api → :8000`;
5. **Параллельная эксплуатация**: Streamlit живёт рядом 1–2 недели после
   зелёного Playwright-сьюта, затем удаляется одним коммитом (фаза 5).

## 9. Первые шаги (можно начать сегодня)

1. `npm create vite@latest webapp -- --template react-ts` + обвязка (
   vite.config с proxy `/api`);
2. `npx openapi-typescript http://localhost:8000/api/openapi.json -o src/api/schema.ts`;
3. клиент `src/api/client.ts` (fetch + refresh-очередь + ApiError) + Vitest;
4. страница логина → CI (lint/typecheck/test/build) → первый коммит
   ветки `webapp/*`.
