## Ключевое решение: heartbeat по арендам

Фоновый heartbeat **не продлевает TTL всем активным сессиям** — иначе сессии
никогда не истекут и сценарий ТЗ «100 дней без работы → архив» стал бы
недостижимым. Вместо этого:

1. клиент с открытой сессией шлёт `POST /api/sessions/{id}/heartbeat`;
2. эндпоинт ставит аренду в `app/core/leases.py` (в памяти процесса);
3. воркер продлевает TTL только сессиям с живой арендой;
4. брошенные сессии аренды не имеют и доходят до `expires_at`.

Побочный эффект в пользу приватности: после рестарта процесса аренды пусты,
поэтому «мёртвые» сессии не воскресают.

## Жизненный цикл

```
active ──pause──▶ paused ──resume──▶ active
   │
   ├──archive (вручную) ──▶ archived
   │
   └──TTL истёк (reaper) ─▶ archived ──retention (30 дней)──▶ purged
                                                  (файлы + чанки удалены)
```

* `paused` — работать можно, сессия закреплена заметкой;
* `archived` — **только чтение**: любые мутации дают 409 (`ConflictError`);
* `purged` — строка остаётся как tombstone (`purged_at`), но документы,
  сообщения, файлы и чанки сессии удалены.

## Точка возврата

`PUT /api/sessions/{id}/state` мержит снапшот (`state_snapshot`) и пишет
служебное поле `saved_at`. Если содержимое не изменилось — запись не делается
(дебаунс 5 минут на клиенте + дедупликация на сервере), но TTL продлевается.
`POST /sessions/{id}/resume` возвращает снапшот, заметку, сводку по лимитам и
реконструирует `Docs` сессии из БД.

## Лимиты (ТЗ) — 409 с внятным сообщением

| Лимит | Значение | Проверка |
| --- | --- | --- |
| Сессий на пользователя | 10 | `create_research_session` |
| Документов на сессию | 50 | `check_document_limits` |
| Хранилище сессии | 500 МБ | `check_document_limits` (по сумме размеров) |
| Проектов на сессию | 5 | `check_project_limit` |

Лимит хранилища считается **до** индексации (по размеру файла на диске или
`UploadFile.size`), поэтому дорогой `aadd` не запускается впустую.

## Персистентность

* `documents` (реестр) и `document_chunks` (чанки) — согласованная пара;
  удаление документа чистит обе части;
* сессионные файлы лежат в `data/sessions/<id>/` — удаление сессии не задевает
  чужие файлы (изоляция сессий);
* `restore_state()` после рестарта пересобирает `Docs` из `document_chunks` без
  повторного парсинга PDF и без пересчёта эмбеддингов.
