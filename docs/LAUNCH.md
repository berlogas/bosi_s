# Как запустить boasi_s

Короткая инструкция. Подробности развёртывания и бэкапов —
[OPERATIONS.md](OPERATIONS.md).

## Самый короткий путь

```bash
cd N:/Development/boasi_s
./scripts/start.sh
```

Откроется на <http://127.0.0.1:8501>.

На Windows можно вместо этого запустить **`scripts\start.bat`** двойным
кликом — он сам найдёт Git Bash (важно: в Windows есть три файла `bash.exe`,
и один из них принадлежит WSL, а не Git; `.bat` их различает).

---

## Что нужно один раз

### 1. Подготовить окружение

```bash
cd N:/Development/boasi_s
cp .env.example .env
```

### 2. Сгенерировать SECRET_KEY

Обязательно: без этого приложение не стартует (проверка в Фазе 9).

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

Скопируйте результат в `.env` в строку `SECRET_KEY=`.

### 3. Зависимости

```bash
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r backend/requirements.lock
```

Если `.venv` уже есть — шаг пропускайте.

### 4. Модель Ollama

Нужна один раз, если модель ещё не скачана:

```bash
ollama serve            # в отдельном окне, если ещё не работает
ollama pull qwen2.5:3b
```

### 5. Создать администратора

Регистрации в интерфейсе нет — учётные записи создаёт админ:

```bash
./scripts/start.sh admin ivanov
```

Скрипт спросит пароль (минимум 8 символов).

Если учётная запись **уже есть**, а пароль забыт:

```bash
./scripts/start.sh users                    # посмотреть, кто заведён
./scripts/start.sh password ivanov          # задать новый пароль
```

> Если `create_admin.py` отвечает «пользователь уже существует» — это не
> ошибка, а значит, что запись уже создана. Смотрите список командой `users`
> и сбрасывайте пароль командой `password`.

## Вход в интерфейс

Откройте <http://127.0.0.1:8501> — на экране форма с полями **Логин** и
**Пароль** и кнопкой «Войти». Регистрации нет: учётные записи создаёт
администратор, пароль выдаётся вместе с логином.

Забыли пароль — с экрана входа или из терминала:

```bash
./scripts/start.sh password <логин>
```

**Форма — в браузере, а не в терминале.** Строки в окне запуска («Вход готов:
admin») — это подсказка консоли, а не способ войти.

## Запуск и остановка

```bash
./scripts/start.sh            # запустить всё
./scripts/start.sh status     # что работает
./scripts/start.sh stop       # остановить backend и интерфейс
./scripts/start.sh restart    # перезапустить
./scripts/start.sh logs backend   # смотреть логи (или frontend)
./scripts/start.sh test       # прогнать тесты
./scripts/start.sh help       # все команды
```

Скрипт **не требует `make`** — на этой машине его нет. `Makefile` оставлен
для тех, у кого `make` установлен.

### Что делает `start.sh`

1. Проверяет Python, зависимости и `.env`; если `SECRET_KEY` пустой или
   шаблонный — **останавливается с инструкцией**, а не падает в логах.
2. Проверяет Ollama и список моделей (предупредит, если моделей нет, но не
   блокирует: backend поднимется и без неё).
3. Запускает backend, **дожидается ответа `/api/health`**, затем интерфейс.
4. Пишет PID в `.run/`, логи — в `logs/`.

Запуск идемпотентный: если процесс уже работает, повторный вызов ничего не
сломает.

### Если что-то не стартовало

```bash
./scripts/start.sh logs backend     # последние строки лога
```

Типичные причины:

| Сообщение | Что делать |
| --- | --- |
| `execvpe(/bin/bash) failed` | `start.bat` подхватил WSL вместо Git Bash — удалите WSL или запустите вручную: `bash scripts/start.sh` |
| `SECRET_KEY шаблонный` | сгенерировать ключ (шаг 2) |
| `Порт 8000 занят` | `./scripts/start.sh stop` или снять старый процесс |
| `Ollama недоступна` | `ollama serve` в отдельном окне |
| `Моделей нет` | `./scripts/start.sh models` |

## Три процесса — если захотите запускать вручную

Скрипт делает это за вас, но иногда нужно видеть вывод в терминале (например,
чтобы следить за логами вживую).

```bash
# 1. Ollama (обычно работает как служба)
ollama serve

# 2. Backend
cd backend
../.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000

# 3. Интерфейс
cd ../frontend
../.venv/Scripts/python.exe -m streamlit run app.py --server.port 8501
```

На Linux/macOS интерпретатор другой: `.venv/bin/python`.

**Останавливать в этом случае нужно вручную** (Ctrl+C в каждом окне): скрипт
`stop` знает только PID из `.run/`, а запущенные вручную процессы он не видит.

## Через Docker

```bash
cp .env.example .env          # + SECRET_KEY, как выше
./scripts/start.sh docker
```

Скрипт скачает модели, соберёт образы и поднимет стек. Остановить:

```bash
docker compose down
```

Отличия от ручного режима: данные в томе `boasi_data` (бэкап-скрипты работают
именно с ним), Ollama доступна по имени `ollama`, а не `127.0.0.1`.

## Настройка портов

Переопределяются переменными окружения:

```bash
API_PORT=9000 UI_PORT=8600 ./scripts/start.sh
```

---

## Проверка, что всё работает

```bash
./scripts/start.sh status
```

Ожидается три зелёные строки. Если backend отвечает `status=degraded`,
смотрите `./scripts/start.sh logs backend` — причина в последних строках.

## Что ещё полезно знать

* Первый ответ занимает **минуты** — это CPU-инференс, не сбой. В интерфейсе
  есть прогресс и кнопка «Отменить».
* Проверка без браузера: <http://127.0.0.1:8000/api/health> и
  <http://127.0.0.1:8000/api/docs> для Swagger.
* Метрики: <http://127.0.0.1:8000/api/metrics.json>.
* Полное состояние проекта, архитектура и известные ограничения —
  [PROJECT_CONTEXT.md](../PROJECT_CONTEXT.md).
