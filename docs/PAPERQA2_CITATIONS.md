# Цитирование и обоснованность (Grounding) в PaperQA2

Описывает, как boasi_s проверяет и чинит маркеры цитат в ответах LLM, чтобы исследователь мог верить источникам.

## Проблема

Слабая офлайн-модель (например, `qwen2.5:3b`) часто выдумывает собственные обозначения источников вместо ключей PaperQA вида `(pqac-xxxxxxxx)`:

- `(степень 1)`, `(уровень 2)`, `(источник 3)` — русские метки с номерами
- `(степень 7)` при 5 источниках — номер за пределами выдачи
- `(2b_context lines 47-77)` — имена фрагментов paperqa вместо номеров

Такие маркеры не разрешаются ни в один источник и оставляют мусор в ответе.

## Решение: `citation_guard.py`

Модуль `app/services/citation_guard.py` реализует функцию `repair_markers(text, source_count, sources=None)` — три прохода, от грубого к точному:

### Проход 1: блок References
Удаляются целые строки блока «References», где ни одна ссылка не разрешилась. Заголовок «References» удаляется, если под ним не осталось ни одной записи.

### Проход 2: маркеры в скобках
- `(степень 1)` → `[1]`
- `(источник 2, источник 2)` → `[2]` (дубликаты схлопываются)
- `(docname lines 47-77)` → `[n]` по имени фрагмента (если передан список `sources`)
- Номера вне диапазона `1..source_count` удаляются целиком

### Проход 3: маркеры без скобок в прозе
`docname lines N-M` в тексте переписывается в `[n]`, только если документ однозначно опознан.

## CitationReport

Каждый вызов `repair_markers()` возвращает отчёт `CitationReport`:

| Поле | Описание |
|------|----------|
| `ok` | Цитаты не оставляют мусора (ничего не удалено, всё разрешимо) |
| `changed` | Текст ответа был исправлен |
| `repaired` | Список исправленных маркеров (для логов, не показывается пользователю) |
| `dropped` | Удалённые маркеры (ссылка в никуда) |
| `reflowed` | Косметические правки («1. [2]:» → «1. [2]») |
| `cited` | Номера `[n]`, найденные в тексте |
| `dangling` | Номера вне диапазона источников |
| `uncited` | Источники есть, но в тексте нет ни одной ссылки |
| `warnings` | Предупреждения для интерфейса |

## API

### `GET /api/pqa/citation-report`

Возвращает `CitationReport` последнего ответа чата (из `stats["citations"]`). Требует прав администратора.

**Response:**
```json
{
  "ok": true,
  "changed": false,
  "repaired": [],
  "dropped": [],
  "reflowed": [],
  "cited": [1, 2],
  "dangling": [],
  "uncited": false,
  "warnings": []
}
```

## Обоснованность фактов: `grounding.py`

Правка маркеров чинит ССЫЛКИ, но не факты. Отдельная проверка
`check_grounding(answer, contexts)` сверяет сущности ответа (именованные
последовательности, годы, числа) с найденными фрагментами: точное вхождение
либо совпадение основ слов (≥ 4 букв — терпит склонения). Цифры и римские
разряды требуют точного токена: именно «1773» вместо «1772» модель выдумывает.

Отчёт `GroundingReport`:

| Поле | Описание |
|------|----------|
| `ok` | Все сущности ответа подтверждены источниками |
| `checked` | Сколько сущностей проверено |
| `grounded` | Сколько подтверждено |
| `ungrounded` | Неподтверждённые сущности (показываются в предупреждении) |
| `warnings` | Предупреждения для интерфейса |

**Контекстом сверки служит исходный текст источников, а не сводки LLM.**
Сводка — пересказ, сделанный той же моделью, что и ответ: если модель выдумала
«105 °C» в сводке, то это же «105 °C» оказалось бы в контексте проверки, и
выдумка прошла бы как подтверждённый факт (случай от 2026-11-11, Ollama 3B).
Исходный текст документа выдумать нельзя — он написан автором.

Проверка показывает **отсутствие опоры в выдаче**, а не доказывает ложь:
факт может быть верен, а документ — написан обтекаемо.

## Где используется

- `RagFusionService.answer()` — после генерации ответа маркеры чинятся через `repair_markers()`, отчёт попадает в `stats["citations"]`.
- `check_grounding()` — отчёт обоснованности попадает в `stats["grounding"]` и в `messages.checks`.
- `ChatQueryResponse.stats` — клиент может отобразить предупреждения о сломанных цитатах.
- Экспорт статей (`export.py`) — цитаты `[n]` в тексте сверяются со сквозным списком литературы.

## Примеры

```python
from app.services.citation_guard import repair_markers

# Выдуманные маркеры чинятся в номера источников
fixed, report = repair_markers(
    "Факт (степень 1, степень 2).",
    source_count=5
)
# fixed == "Факт [1, 2]."
# report.repaired == ["(степень 1, степень 2) → [1, 2]"]

# Номер вне диапазона удаляется
fixed, report = repair_markers(
    "Утверждение (степень 7).",
    source_count=5
)
# fixed == "Утверждение."
# report.dropped == ["(степень 7)"]

# Имя фрагмента paperqa резолвится в номер
fixed, report = repair_markers(
    "Факт (2b_context lines 47-77).",
    source_count=3,
    sources=[{"index": 2, "docname": "2b_context", "page": "2b_context lines 47-77"}]
)
# fixed == "Факт [2]."
```
