# Интеграция boasi_s с PaperQA2

Описывает, как boasi_s использует библиотеку `paper-qa` (v2026.8.12) для локального научного RAG без интернета и внешних баз.

## Архитектура

```
┌─────────────────────────────────────────────────────────────┐
│                    boasi_s FastAPI                           │
│  /api/chat/query  /api/pqa/reindex  /api/pqa/citation-report│
└─────────────────────────────────────────────────────────────┘
                              │
┌─────────────────────────────────────────────────────────────┐
│              app/services/paperqa_service.py                │
│        PaperQA2Service — обёртка над paperqa.Docs            │
└─────────────────────────────────────────────────────────────┘
                              │
┌─────────────────────────────────────────────────────────────┐
│              app/services/pqa_registry.py                   │
│        ServiceRegistry — реестр коллекций                    │
│        - "global" — глобальная база знаний                   │
│        - "session:<id>" — личная база исследователя          │
└─────────────────────────────────────────────────────────────┘
                              │
┌─────────────────────────────────────────────────────────────┐
│              app/services/pqa_profile.py                    │
│        build_pqa_settings() — бумажные настройки paperqa     │
│        settings_fingerprint() — отпечаток конфигурации       │
└─────────────────────────────────────────────────────────────┘
                              │
┌─────────────────────────────────────────────────────────────┐
│              app/services/chunk_store.py                    │
│        SqliteChunkStore — персистентность чанков (Doc + Text)│
│        SCHEMA_VERSION = 1 — версия схемы хранения             │
└─────────────────────────────────────────────────────────────┘
                              │
                    paper-qa 2026.8.12
                    (Docs, PQASession, aquery, aget_evidence)
```

## Коллекции

| Коллекция | Назначение | Кто пишет |
|-----------|------------|-----------|
| `global` | Глобальная база знаний (доступна всем) | Администратор через `/api/admin/documents/upload` |
| `session:<uuid>` | Личная база исследователя (изоляция сессий) | Исследователь через загрузку в сессию |

Реестр: `ServiceRegistry.get(collection)` — ленивое создание `PaperQA2Service` с одним экземпляром `paperqa.Docs` на коллекцию.

## Жизненный цикл документа

1. **Загрузка** — `PaperQA2Service.add_file()` вызывает `Docs.aadd()` с путем к файлу, цитированием и docname.
2. **Дедупликация** — по `dockey` (MD5 содержимого файла). Повторная загрузка того же файла без `force_reindex` возвращает `None`.
3. **Персистентность** — `PaperQA2Persistence.persist_state()` сохраняет `Doc` + `Text` (zlib + JSON) в таблицу `document_chunks` SQLite. Эмбеддинги хранятся вместе с текстом, не пересчитываются при восстановлении.
4. **Восстановление** — `PaperQA2Persistence.restore_state()` загружает чанки из БД через `Docs.aadd_texts()`, пропуская записи с несовпадающим `settings_md5` или `schema_version`.

## Публичные методы PaperQA2Service

| Метод | Назначение |
|-------|------------|
| `add_file(path, ...)` | Добавить один файл в коллекцию |
| `add_files(paths, ...)` | Добавить несколько файлов |
| `add_uploads(files, ...)` | Добавить загруженные через HTTP файлы |
| `add_url(url, ...)` | Добавить документ по URL |
| `delete_document(dockey\|path\|docname)` | Удалить документ из коллекции |
| `clear_documents()` | Очистить всю коллекцию |
| `list_documents()` | Список документов в памяти |
| `documents_on_disk()` | Реестр документов из БД |
| `stats()` | Статистика коллекции |
| `get_evidence(query, k, ...)` | Найти контекст без генерации ответа |
| `search(query, limit)` | Поиск фрагментов без ответа |
| `ask(query\|PQASession, ...)` | Ответить на вопрос (базовый RAG) |
| `ask_with_evidence(query, k, ...)` | RAG-fusion: контекст → ответ без повторного поиска |
| `agent_ask(query, ...)` | Ответ через PaperQA-агент (итеративный поиск) |
| `persist_state()` | Сохранить состояние Docs в хранилище |
| `restore_state(force)` | Восстановить Docs из хранилища |
| `rebuild_index(drop_embeddings)` | Полная переиндексация коллекции |
| `complete(prompt, ...)` | Один вызов LLM |
| `stream_complete(prompt, ...)` | Потоковый вызов LLM |
| `embedding_relevance(question, contexts)` | Косинусное сходство вопроса к контекстам |

## Режимы ответа

### Базовый RAG (`mode=hybrid`)
Один вызов `Docs.aquery()` на объединённом контексте из глобальной и сессионной коллекций. Быстро (секунды), подходит для простых вопросов.

### Агент (`mode=agent`)
Итеративный поиск через `paperqa.agents.agent_query()`. Агент сам выбирает инструменты: поиск документов, сбор доказательств, генерацию ответа. Медленнее (несколько вызовов LLM), подходит для сложных вопросовrequiring синтеза из нескольких документов.

Выбор режима — в веб-интерфейсе чата (селектор «Источник»).

## Персистентность и схемы

- `SCHEMA_VERSION = 1` в `chunk_store.py` — при изменении структуры `doc_blob`/`texts_blob` увеличивается, старые записи помечаются устаревшими.
- `settings_fingerprint` — MD5 текущих настроек PaperQA. При смене модели эмбеддингов, размера чанка или других параметров старые чанки пропускаются при `restore_state()` и требуют переиндексации.

## API-эндпоинты PaperQA2

| Эндпоинт | Метод | Описание | Права |
|----------|-------|----------|-------|
| `/api/pqa/reindex` | POST | Полная переиндексации коллекции | Админ |
| `/api/pqa/citation-report` | GET | Отчёт о цитировании последнего ответа | Админ |
| `/api/admin/documents/reindex` | POST | Переиндексация через админку документов | Админ |

## Отсутствие интернета

В автономном контуре:
- ЛLM — локальная Ollama (без GPU — CPU)
- Эмбеддинги — локальные sentence-transformers (мультиязычные)
- Нет Crossref / Semantic Scholar (`OFFLINE_MODE=true`)
- Нет PaperSearch (требует интернета)
