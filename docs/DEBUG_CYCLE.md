# Отладочный цикл работы с boasi_s (Docker)

Полный сценарий отладки: от запуска стека до проверки бэкапа и восстановления.
Прогоняйте по шагам, чтобы убедиться, что платформа работает корректно после развёртывания или изменений кода.

---

## Этап 0. Подготовка (один раз)

```cmd
cd N:\Development\boasi_s

rem 1. Проверить, что .env есть и SECRET_KEY не шаблонный
findstr /i "SECRET_KEY=" .env

rem 2. Если нет — сгенерировать и вставить в .env
python -c "import secrets; print(secrets.token_urlsafe(48))"

rem 3. Создать нужные папки на хосте
mkdir inbox backups logs .run
```

---

## Этап 1. Запуск стека

```cmd
scripts\start-docker.bat
```

### Что должно произойти
1. Скрипт проверит Docker, `.env`, `SECRET_KEY`.
2. Поднимется Ollama (образ `ollama/ollama:latest`).
3. Соберётся и запустится backend (`boasi-backend`, порт 8000).
4. Соберётся и запустится webapp (`boasi-webapp`, порт 5173).
5. Откроется браузер на `http://127.0.0.1:5173`.

### Проверить
```cmd
scripts\start-docker.bat status
```

Ожидается три контейнера в статусе `Up`:
- `boasi-ollama`
- `boasi-backend`
- `boasi-webapp`

```cmd
curl -fsS http://127.0.0.1:8000/api/health
```

Должен вернуть JSON со статусом `ok` или `degraded` (если модель Ollama ещё не загружена).

## Этап 2. Создать администратора

```cmd
docker compose exec backend python scripts/create_admin.py odmin
```

Ввести пароль (минимум 8 символов). Запомнить логин/пароль — они понадобятся для входа в UI.

Альтернативно, обычный исследователь создаётся админом через вкладку **Пользователи** в интерфейсе.

---

## Этап 3. Первый вход в интерфейс

1. Открыть `http://127.0.0.1:5173`.
2. Войти под логином `odmin` и паролем.
3. Попасть на информационную панель.

### Проверить
- Вкладка **Администрирование** доступна (роль `admin`).
- В меню слева есть: Сессии, Документы, Проекты, Чат, База знаний, Администрирование.

---

## Этап 4. Создать сессию

1. На информационной панели нажать **«Новая сессия»**.
2. Название: `Отладка цикла работы`.
3. Сохранить.

### Ожидаемый результат
- Сессия появляется в списке «Мои сессии».
- Срок жизни: 90 дней (отображается на карточке).
- Сессия открывается в рабочее пространство.

---

## Этап 5. Загрузить документы в сессию

Внутри сессии открыть вкладку **«Документы»**.

### Загрузка 1 — CSV с данными
1. Выбрать категорию **«Данные»**.
2. Теги: `хлорофилл, биомасса`.
3. Перетащить файл с данными (например, `demo/barents-article/barents_stations_2026.csv`).
4. Нажать **«Загрузить»**.

### Загрузка 2 — статья (литература)
1. Выбрать категорию **«Временная литература»**.
2. Теги: `хлорофилл-а`.
3. Перетащить `.md` или `.pdf` файл со статьёй.
4. Нажать **«Загрузить»**.

### Загрузка 3 — черновик
1. Выбрать категорию **«Черновики проекта»**.
2. Перетащить файл черновика статьи.
3. Нажать **«Загрузить»**.

### Проверить индексацию
- Подождать, пока все файлы получат статус **«готово»** (не «в индексации», не «ошибка»).
- Если ошибка — проверить логи: `scripts\start-docker.bat logs backend`.
- Лимит: не более 50 документов и 500 МБ на сессию.

## Этап 6. Проверить чат (RAG)

Внутри сессии открыть вкладку **«Чат»**.

### Тестовый вопрос 1 (гибридный поиск)
Режим: **«Гибридный»**.
Вопрос: *«Какие значения хлорофилла а зафиксированы на станциях Баренцева моря?»»

 ┌───────────────────┬──────────────────────────────────────────┬─────────────────────────────────────────────────────┐
 │                   │ Стриминг выключен                        │ Стриминг включен                                    │
 ├───────────────────┼──────────────────────────────────────────┼─────────────────────────────────────────────────────┤
 │ Запрос            │ POST /chat/query-async → task_id         │ chatStream → SSE-токены                             │
 ├───────────────────┼──────────────────────────────────────────┼─────────────────────────────────────────────────────┤
 │ Где ответ сначала │ В фоновой задаче на сервере              │ Постепенно в локальном стейте streamingAnswer       │
 ├───────────────────┼──────────────────────────────────────────┼─────────────────────────────────────────────────────┤
 │ Ответ в истории   │ Сразу после done через                   │ Добавляется вручную в setLast() после закрытия      │
 │                   │ /api/chat/messages                       │ потока                                              │
 ├───────────────────┼──────────────────────────────────────────┼─────────────────────────────────────────────────────┤
 │ TaskPanel         │ Показывает этапы и проценты              │ Не показывается                                     │
 └───────────────────┴──────────────────────────────────────────┴─────────────────────────────────────────────────────┘
### Ожидаемое поведение
1. Появляется панель прогресса: поиск → переранжирование → генерация → проверка цитат.
2. Ответ занимает минуты (CPU-инференс через Ollama).
3. Под ответом есть ссылки на источники:
   - 📁 — файлы из сессии (загруженные вами).
   - 📚 — документы из глобальной базы (если админ их загружал).
4. Кнопка **«Отменить»** прервёт задачу на ближайшем шаге.

### Тестовый вопрос 2 (только сессия)
Режим: **«Только сессия»**.
Вопрос: *«Что написано в моём черновике про методы сбора?»»

### Ожидаемое поведение
- Ответ должен опереться только на загруженные в сессию файлы.
- Если в черновике нет такого текста — модель честно скажет, что материала недостаточно.

## Этап 7. Создать проект и сгенерировать раздел

Внутри сессии открыть вкладку **«Проекты»**.

1. Нажать **«Новый проект»**.
2. Название: `Статья: хлорофилл в Баренцевом море`.
3. Платформа предложит план разделов:
   - Введение
   - Материалы и методы
   - Результаты
   - Обсуждение
   - Заключение

### Сгенерировать раздел
1. Нажать на раздел **«Результаты»**.
2. Нажать **«Сгенерировать»**.
3. Дождаться ответа (минуты).
4. Проверить, что в тексте есть ссылки на загруженные документы (ссылки на источники с номерными цитатами).
5. Отредактировать текст вручную при необходимости.
6. Нажать **«Сохранить версию»**.

## Этап 9. Бэкап (сохранить состояние)

```cmd
rem Остановить стек (обязательно перед бэкапом для консистентности БД)
scripts\start-docker.bat stop

rem Сделать бэкап (Git Bash)
bash scripts/backup.sh
```

### Ожидаемый результат
- Архив `backups/boai-YYYYmmdd-HHMMSS.tar.gz`.
- Файл контрольной суммы `*.sha256`.
- Внутри: снимок SQLite, файлы сессий и документов, манифест.

### Проверить бэкап
```bash
bash scripts/verify_backup.sh backups/boai-YYYYmmdd-HHMMSS.tar.gz
```

Должно вывести:
```
[ok] boasi.sqlite3: NNNN байт
[ok] integrity_check: ok
ок бэкап пригоден для восстановления
```

## Этап 10. Восстановление (проверить, что бэкап живой)

```cmd
rem Убедиться, что стек остановлен
scripts\start-docker.bat stop

rem Восстановить (ввести слово ВОССТАНОВИТЬ при запросе)
bash scripts/restore.sh backups/boai-YYYYmmdd-HHMMSS.tar.gz

rem Запустить стек снова
scripts\start-docker.bat start

rem Проверить
scripts\start-docker.bat status
curl -fsS http://127.0.0.1:8000/api/health
```

### Ожидаемый результат
- Страховочная копия текущего состояния сохранится в `backups/pre-restore/`.
- После запуска сессия, документы и проекты на месте.
- Администратор и пользователи сохранены.

## Этап 11. Логи и диагностика (если что-то пошло не так)

```cmd
scripts\start-docker.bat logs backend     # логи backend
scripts\start-docker.bat logs webapp      # логи веб-интерфейса
scripts\start-docker.bat logs ollama      # логи Ollama
scripts\start-docker.bat status           # состояние контейнеров
```

### Типичные ошибки при отладке

| Симптом | Причина | Решение |
|---------|---------|---------|
| Backend не отвечает на `/api/health` | Erste загрузка модели эмбеддингов (минуты) | Подождать, проверить `logs backend` |
| Чат не отвечает | Модель Ollama не скачана | `docker exec -it boasi-ollama ollama pull qwen2.5:3b` |
| Документ не индексируется | Неподдерживаемый тип или > 200 МБ | Проверить `logs backend`, категорию файла |
| SECRET_KEY шаблонный | Не заменён в `.env` | Сгенерировать новый ключ, перезапустить |

## Этап 12. Остановка и повторный запуск

```cmd
rem Остановить (данные в томах остаются)
scripts\start-docker.bat stop

rem Снова запустить
scripts\start-docker.bat

rem Пересобрать после правок кода backend
scripts\start-docker.bat rebuild-backend
```
