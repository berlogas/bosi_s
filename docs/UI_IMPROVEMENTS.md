## Навигация и каркас

- **Активный пункт меню ломается внутри сессии.** `AppLayout.tsx` сравнивает
  `location.pathname === item.to`, а «Текущая сессия» ведёт на `/s/:id`; на
  `/s/:id/chat` пункт неактивен. Нужен `startsWith`/вложенный `NavLink`.
- **Нет хлебных крошек и переключателя сессий.** Из сессии можно выйти только на
  дашборд. Предложение: «Панель / Сессия / Чат» + дропдаун последних 5 сессий в
  сайдбаре.
- **Дашборд начинается с QuickChat**, затем задачи, создание сессии, и только потом
  «Мои сессии» (`DashboardPage.tsx`). Для возвращающегося исследователя главное —
  ниже сгиба. Варианты: две колонки (сессии слева, быстрый чат справа) или
  свёрнутый по умолчанию QuickChat с сохранением состояния.
- **QuickChat растёт вниз на 20 сообщений** (`useQuickHistory(limit = 20)`) и
  отодвигает сессии. Логичнее ограничить высоту `ScrollArea` или вынести в
  отдельную страницу/панель.
- **`index.html`: `lang="en"`** при русскоязычном интерфейсе — поправить на `ru`
  (влияет на скринридеры, переносы, орфографию).
- **Нет `ErrorBoundary`**: ошибка рендера любой страницы роняет всё приложение.
  Обернуть route-элементы.
- **Нет глобальных уведомлений** кроме админки (`notifications` используется только
  в `admin/queries.ts`). Успешная загрузка, сохранение статуса, экспорт заслуживают
  тоста.

## Чат

- **Композер должен быть закреплён внизу** и быть `Textarea` с `autosize`,
  Enter — отправить, Shift+Enter — перенос (паритет с QuickChat).
- **Режим поиска и «Фоновый режим» занимают отдельную строку.** Компактнее: режим —
  `SegmentedControl`/меню в композере, фоновый режим — настройка с подсказкой, а не
  постоянный `Switch`.
- **Удаление пары**: `loading={deleteMessage.isPending}` навешан на все кнопки
  сразу — при удалении одного сообщения крутятся все. Нужен pending по `message.id`;
  лучше — undo-тост вместо необратимого удаления.
- **Нет виртуализации и управления скроллом**: история растёт, «Показать более
  ранние» добавляет по 100 сообщений. `@tanstack/react-virtual` + кнопка «вниз» +
  индикатор непрочитанного.
- **Ошибки и отмена** обрабатываются хорошо, но панель задачи исчезает при уходе со
  страницы. См. п. 1 топа.
- **Оценка времени**: в сообщениях есть `duration_seconds`; можно показывать
  «обычно 2–4 мин» рядом с режимом и медиану по последним ответам — снижает
  тревожность ожидания.
- **Стриминг ответа** (хотя бы финальной генерации) дал бы наибольший прирост
  воспринимаемой скорости; если PaperQA2 не позволяет, честно оставить прогресс
  этапов.

## Документы

- **Добавление по пути — основной сценарий**, drag&drop — вторичный. Для
  исследователя путь на диске сервера — низкоускорный паттерн. Предложить
  переключатель «Файл / Путь», путь — в «для администратора».
- **Теги через запятую** (`TextInput`) заменить на `TagsInput`; категорию — на
  бейджи/сегменты.
- **Выбранные файлы показываются одной строкой** через `join(', ')` — при 10 файлах
  нечитаемо. Список с удалением по одному и размером.
- **Ошибки загрузки только числом**: «Добавлено: N, ошибок: M», без имён файлов и
  причин. Показывать построчно.
- **Нет подсказки о форматах и лимитах** у dropzone — добавить
  «PDF, DOCX, MD, CSV · до X МБ».
- **Удаление документа без подтверждения** — тост с undo либо модалка.
- **Строка документа не раскрывается**: нет просмотра чанков/статуса/ошибки
  индексации, только `dockey.slice(0, 8)`.
- **Аккордеон по категориям** лучше заменить на таблицу с фильтрами/поиском и
  сортировкой, когда документов много.

## Проекты

- **Вся работа в одной длинной колонке**: инструкция → создание → выбор → статус →
  прогресс → экспорт → генерация → разделы → документы. Нужен master-detail: список
  проектов слева, редактор справа; экспорт — в шапку проекта.
- **`HowToPanel` рендерится всегда**, даже когда проектов много. Свернуть в
  `Accordion`/popover, показывать развёрнутым только при пустом списке.
- **Нет UI версий и diff**, хотя API готов. Для научного текста это ключевая
  функция доверия: сравнить «до/после генерации», откатиться.
- **Нет индикатора несохранённых изменений** и предупреждения при уходе; `drafts` в
  `sessionStorage` теряются молча. Добавить бейдж «есть несохранённые правки»,
  автосейв с debounce, `beforeunload`.
- **Генерация раздела синхронная** — только текст «это может занять минуты», без
  отмены. Перевести на тот же фоновый механизм, что чат.
- **Статус проекта меняется через Select + «Обновить»** — лишний шаг; сохранять по
  изменению с индикатором.
- **«Разбор черновика» выводит markdown в `Alert`** — сделать структурный список с
  severity-бейджами и переходом к разделу.

## База знаний и админка

- **Поиск применяется по Enter, а категория — сразу** (`KnowledgePage.tsx`):
  несогласованно. Либо debounce-поиск по вводу, либо обе фильтрации по кнопке.
- **Таблица без сортировки, пагинации и раскрытия строки.** Нужны сортируемые
  колонки, `Table.ScrollContainer` и drawer с citation/тегами/фрагментами.
- **«Управлять базой» ведёт в `/admin` без выбора вкладки** — нужен deep link на
  «Глобальная база».
- **Вкладки админки не в URL** (в отличие от вкладок сессии) — F5 сбрасывает на
  первую. Сделать `/admin/users`, `/admin/knowledge`, `/admin/tasks`, `/admin/audit`.
- **`AdminPage.tsx` — 1721 строка**: разбить на страницы/компоненты, иначе любая
  правка UI дорогая.
- **Аудит и таблицы**: sticky header, фильтры по пользователю/действию/датам;
  экспорт уже есть — вынести кнопку на видное место.
- **Деструктивные действия** (удаление пользователя, сброс) уже с подтверждением —
  хорошо; стоит добавить «danger zone»-группировку и typed confirmation для сброса
  (частично есть).

## Общий дизайн и доступность

- **Иконки**: эмодзи (`📚`, `👤`, `🗑`, `➤`, `⚠️`, аватары `👨‍🔬/👨‍💻`) выглядят
  по-разному в Windows/macOS/Linux и ломают вертикальный ритм.
  `@tabler/icons-react` — родной для Mantine, заменить эмодзи в кнопках и навигации;
  эмодзи оставить только как акценты.
- **Кликабельные `Text` с `role="button"`** в `AnswerView`, `ChecksView`,
  QuickChat-подсказках не фокусируются и не работают с клавиатуры. Заменить на
  `Anchor component="button"`/`UnstyledButton`.
- **Skeleton-состояния** для карточек сессий, истории чата, таблиц; сейчас голый
  `Loader` и layout прыгает.
- **Empty states с действием**: «Документов пока нет» → кнопка «Загрузить первый»;
  «Проектов нет» → фокус на поле названия; пустая база знаний → ссылка для админа.
- **Единый `PageHeader`** (заголовок + описание + действия) и `StatusBadge`; сейчас
  заголовки и бейджи продублированы в каждой странице.
- **`shortWhen` показывает UTC без перевода**: `iso.slice(0,16)` (`lib/format.ts`) —
  использовать `Intl.DateTimeFormat` с локальной зоной и подсказкой полной даты.
- **Мобильная раскладка**: `navbar.collapsed.mobile = false` — сайдбар всегда
  открыт. Нужны `Burger`, `collapsed: { mobile: true }`, скрытие «Состояния
  системы» в popover, горизонтальный скролл таблиц.
- **Тёмная тема**: чек-лист её требует, но `MantineProvider` без переключателя и
  `ColorSchemeScript`. Либо реализовать, либо убрать пункт из приёмки.
- **Мелкая типографика**: `size="xs" c="dimmed"` массово используется для важных
  вещей (срок хранения, теги, источники). Проверить контраст и поднять ключевые
  подписи до `sm`.

## Что уже хорошо и не требует правок

Разделение вкладок сессии на маршруты, автосохранение вкладки, восстановление
фоновой задачи после F5, двухшаговые подтверждения архива/очистки, санитизация
markdown и кликабельные цитаты, отмена задач, панель этапов с секундомером,
обработка `base_empty` и предупреждений grounding — это сильные места, их стоит
сохранить при редизайне.

# План реализации топ-10

Порядок волн выбран по зависимостям, а не по номерам: сначала дешёвые
самостоятельные улучшения, затем общий каркас (шапка/тема/мобильный layout),
потом функции, которым этот каркас нужен.

| Волна | Пункты | Зачем такой порядок |
|---|---|---|
| 1. Быстрые победы | 3, 7, 8, 4 | Не зависят от темы и шапки; закрывают реальные потери данных и неудобства |
| 2. Каркас | 5 → 1 + 6 | Сначала токены/иконки, затем общая шапка, в которой живут ящик задач, Burger и переключатель темы |
| 3. Функции | 2, 9, 10 | Требуют стабильных компонентов (`PageHeader`, `EmptyState`, `SourceList`) и добавляют новые панели |

Оценки — в человеко-днях одного разработчика, знакомого с кодовой базой.
«Строк» — ориентир на дифф, а не жёсткий план.

## 1. Глобальный ящик задач и уведомления

**Шаги**

1. Поднять подписку на задачи на уровень layout: один `EventSource` на
   приложение, а не по одному на каждый вызов `useActiveTasks`. Сейчас хук
   открывает поток в `useEffect` и закрывает его после первой завершённой
   задачи (`dashboard/queries.ts`); сервер тоже обрывает поток на первой
   `finished` (`backend/app/api/tasks.py:78`). В итоге события по остальным
   задачам теряются. Убрать `break` на сервере (или не закрывать
   `EventSource` и дать ему переподключиться; первый вариант чище).
2. Добавить `AppShell.Header` (высота 56px) с индикатором «N задач», кнопкой
   раскрытия списка и `Burger` для мобильных. Сам список — `Popover`/`Drawer`
   с компактными `TaskPanel`.
3. Сравнивать предыдущий и новый статус задачи в одном месте; при переходе в
   `done/error/cancelled` показывать `notifications.show` один раз на задачу.
   Начальный снимок при монтировании не озвучивать, иначе F5 даст пачку
   тостов о старых задачах.
4. Убирать завершённые задачи из кэша `activeTasks` после показа уведомления
   (сейчас завершённая задача может остаться в списке, потому что опрос
   выключается, как только активных не осталось).
5. Оставить `ActiveTasks` на дашборде как расширенный вид; в шапке — только
   счётчик и последние 3–5 задач.

**Критерии приёмки**

- Задача, запущенная в чате или при индексации, видна в шапке с любой
  страницы; счётчик совпадает с числом `queued/running`.
- «Отменить» из шапки отправляет `POST /api/tasks/{id}/cancel` и меняет статус
  на «Отменяется…», затем на `cancelled`.
- При завершении приходит ровно один тост; повторный рендер, переход между
  вкладками и F5 не дублируют уведомление.
- Завершённая задача исчезает из ящика; при нуле активных счётчик скрыт.
- `EventSource` не закрывается после завершения одной задачи: события по
  второй продолжают приходить (проверить двумя параллельными задачами).
- Админ видит задачи всех пользователей, исследователь — только свои
  (совпадает с `GET /api/tasks`).

**Оценка:** L, 2–4 дня.

## 3. «Возобновить» для paused-сессии

**Шаги**

1. Добавить `useResumeSession` в `dashboard/queries.ts`: `POST
   /api/sessions/{id}/resume`, инвалидация `sessionDetail` и `sessions`.
2. В `SessionCard` развести действия: `paused` → основная кнопка
   «Возобновить»; `active` → «Продолжить»; `archived` → обе отключены.
   «Возобновить» вызывает мутацию, показывает `restored_documents` в тосте и
   переходит на `/s/{id}/{tab}` из `state` (fallback `chat`).
3. В `SessionPage` для `paused` показывать `Alert` с кнопкой «Возобновить» —
   пользователь может прийти по прямой ссылке или из истории браузера.

| 8. Skeleton | S, 1–1.5 д | — |
| 4. Sticky-композер | S, 0.5–1 д | — |
| 5. Дизайн-слой | L, 4–6 д | — |
| 6. Тёмная тема + мобильный | M, 2–3 д | 5 |
| 1. Ящик задач | L, 2–4 д | 5 (шапка), 6 (Burger) |
| 2. Версии и diff | M, 2–3 д | 5 (панели) |
| 9. Автосейв черновиков | M, 2–3 д | — |

Итого: **17–26 человеко-дней** на одного разработчика. Бэкенд почти не
затрагивается: в п. 1 нужна одна правка SSE-цикла, остальное — фронтенд.
Основные риски:

- **`schema.ts` генерируется** — не править руками; после изменений API
  запускать `npm run codegen` и `npm run codegen:check`.
- **Один `EventSource`**: при подъёме подписки в layout легко получить два
  потока (StrictMode в dev монтирует эффект дважды) — нужен guard/ref.
- **Автосейв и генерация** конкурируют за один раздел: без блокировки
  последний ответ затрёт свежий текст. Нужен явный выбор пользователя.
- **Undo удаления** без soft-delete на бэкенде невозможен: в п. 7 сознательно
  только подтверждение.
- **Тёмная тема** выявит все хардкоды цветов; без п. 5 правки придётся делать
  дважды.
- **Playwright** требует запущенного backend; новые сценарии (мобильный,
  тема, sticky) стоит помечать, чтобы они не блокировали быстрый прогон.

## Порядок приёмки

1. Юнит-тесты: `cd webapp && npm test`.
2. Типы и линт: `npm run typecheck && npm run lint`.
3. E2E: `npm run test:e2e` (backend поднят).
4. Ручная проверка по `docs/REACT_UI_CHECKLIST.md`, добавить пункты:
   ящик задач, версии/diff, resume, sticky-композер, тёмная тема, мобильный
   drawer, подтверждение удаления, skeleton, автосейв, сниппеты источников.
