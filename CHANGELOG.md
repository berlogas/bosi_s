### Added
- Вкладка «Проекты»: панель сборки статьи (`GET .../manuscript`) — текст, объём, список литературы, замечания
- Вкладка «Проекты»: глоссарий терминов проекта (`GET/POST/DELETE .../glossary`) и проверка терминологии (`GET .../terminology-check`)
- Вкладка «Проекты»: семантический diff версий раздела (`GET .../section-plans/{id}/diff`)
- Вкладка «Проекты»: перевод раздела на язык языковой политики (`POST .../section-plans/{id}/translate`)
- Вкладка «Проекты»: проверка соответствия стилю журнала (`POST .../style-compliance`)
- Вкладка «Проекты»: предгенерационная проверка готовности (`POST .../pre-generation-check`) — запускается по кнопке
- Вкладка «Проекты»: пакетная перегенерация устаревших разделов (`POST .../batch-regenerate`)
- Загрузка документов в сессию стала фоновой: `POST /api/sessions/{id}/documents/upload-async` отвечает `task_id`, индексация идёт в фоне с прогрессом по файлам (было: HTTP-запрос висел на минуты)
- Переиндексация документа из интерфейса: кнопка в строке глобальной базы и флажок в сессии (`force_reindex`)
- Загрузка файла с тем же именем спрашивает подтверждение замены прежней версии — раньше изменённый файл ложился рядом со старым, а тот оставался в индексе
- Итог загрузки показывает, что произошло с каждым файлом: сколько добавлено, сколько дубликатов, какие файлы не разобрались и почему
- Вкладка «Проекты»: перетаскивание проектов для сортировки; в `projects` заведена колонка `order` (миграция `add_order_to_project`)
- Админка, «Обслуживание»: подтверждение снятия резервной копии отдельным окном
- Заметки по ходу рефакторинга перенесены в `docs/wip/` (с `README.md`), корень репозитория очищен
- 11 тестов на новые панели вкладки «Проекты» (`projectsPanels.test.tsx`) и тест на порядок проектов в бэкенде
- E2E-набор на новые панели (`e2e/projects-panels.spec.ts`): панели проверяются в настоящем браузере, скриншоты — в `e2e/__screenshots__/`

- Вынесение `PaperQA2Persistence` в `pqa_persistence.py` — отдельный модуль для персистентности
- Добавлены delegate-методы на `PaperQA2Service`: `persist_state()`, `restore_state()`, `rebuild_index()`
- Исправлена типизация: `token_generator() -> AsyncIterator[str]` в `chat.py`
- Исправлена типизация: `ProjectVersionModel` вместо `ProjectVersion` в `projects.py`
- Добавлена аннотация `**kwargs: Any` в `pqa_readers.py`
- Обновлена документация: `RECOMMENDATIONS.md` п.3 помечена выполненным
- Перенесен `get_registry` и связанные импорты из `paperqa_service.py` в `pqa_registry.py`
- Исправлены неиспользуемые импорты: `from sqlalchemy import select` удален из `documents.py`
- Обновлены пути к базе данных и настройки окружения
- Обновлена конфигурация `litellm` для поддержки модели `ministral-3b-latest`
- Удалён мёртвый код вкладки «Проекты» (`useSectionEditor`, `useGeneration`, `useProjectDrafts`, `drafts.ts` и часть хуков/методов клиента)
- ESLint по всему фронтенду (`webapp/src`) приведён к нулю ошибок; `tsc -b --force` — без ошибок
- Контракт OpenAPI (`webapp/openapi/spec.json`) перегенерирован и совпадает с кодом

### Fixed
- Чат мог «молчать» без ответа: ожидание LLM-сводок при поиске ограничено (`EVIDENCE_SUMMARY_TIMEOUT_SECONDS`, по умолчанию 120 с), после таймаута поиск идёт по эмбеддингам
- Если задача чата потерялась (перезапуск backend), вопрос больше не исчезает из переписки молча — показывается ошибка с текстом вопроса
- Чат отвечал «база данных пуста» при полной базе: отпечаток чанков теперь версионирован (`v2:`), а записи старого формата восстанавливаются и пересохраняются вместо того, чтобы молча считаться устаревшими (`pqa_persistence.restore_state`)
- Ответ без RAG-контекста больше не утверждает «база пуста», если документы в базе есть: промпт и флаг `base_empty` говорят о том, что нашлось по запросу
- Исправление F821: `ProjectVersion` → `ProjectVersionModel` в `projects.py`
- Исправление ANN202: `token_generator` добавлена возвращаемая аннотип типа `AsyncIterator[str]`
- Исправление ANN003: `**kwargs: Any` добавлен в `pqa_readers.py`
- Удаление неиспользуемых imports в `documents.py` (`from sqlalchemy import select`)
- Purge сессии больше не удаляет файлы глобальной базы: удаляются только файлы внутри каталога сессии (`services/session_cleanup.py`)
- Явное удаление сессии (`DELETE /api/sessions/{id}`) чистит её файлы и коллекцию чанков — раньше они оставались до purge по TTL
- Фоновая индексация больше не использует сессию БД из HTTP-запроса: своя сессия на задачу (`bulk-async` и новая загрузка в сессию)
- `POST /api/admin/documents/bulk-async` теперь проверяет пути импорта, как `bulk-add`: раньше можно было проиндексировать любой файл на диске в обход `ALLOW_EXTERNAL_IMPORT_PATHS`
- Переиндексация документа через интерфейс: `force_reindex` теперь уходит из кнопки «Переиндексировать» (глобальная база) и флажка «Переиндексировать…» (сессия)
- Загрузка файла с тем же именем спрашивает подтверждение замены версии; при согласии старая версия удаляется из индекса и реестра (`services/document_replace.py`)
- Итог загрузки документов показывает добавленные/дубликаты/ошибки по каждому файлу (`failed`/`duplicates` в UI)
- Временные файлы загрузки теперь удаляются при ошибке индексации или дубликате (`index_staged`, `add_url`); размер файла проверяется до чтения в память (`stage_uploads`)
- Удалён мёртвый код сервиса: первое (неиспользуемое) определение `add_file` и метод `add_url`/`ConflictDocument` (не подключены к API)
- Сессионная загрузка (`upload`, `upload-async`) отклоняет категорию `global_knowledge` — она доступна только для глобальной базы
- Удаление документа (`DELETE /api/{admin/}documents[/...]`) теперь удаляет файл с диска с проверкой принадлежности области
- Перетаскивание проектов в списке не работало: не было `DndContext`, а в бэкенде отсутствовало поле `order`
- Ручка перетаскивания перехватывала клики по элементам управления внутри карточки проекта
- Ошибка отправки вопроса в чате терялась — теперь показывается сообщением
- Ошибка изменения статуса проекта больше не теряется
- `useState` вызывался условно в `NavSection.tsx` — React ломал порядок хуков
- Пункт меню «Текущая сессия» гас после смены сессии: путь читался из хранилища без реактивности
- Удалены отладочные `DEBUG:`-принты из `backend/app/api/projects.py`
- Форматтер логов больше не падает на некорректной записи от сторонней библиотеки

## [0.1.0] - 2026-10-28

### Added
- Initial release of boasi_s — локальная научная RAG-платформа на PaperQA2 + Ollama + FastAPI + React
- Фазы 0-9 реализованы: загрузка документов, поиск, генерация ответов, управление сессиями, RAG Fusion, проекты статей, Docker-развертывание
- Создан `docs/wip/PHASE10_ACCEPTANCE.md` с чеклистом приёмки по сценарию
- Настроен `alembic` для миграций базы данных
- Настроен `ollama` с моделями `qwen2.5:3b` и `nomic-embed-text`

### Fixed
- Пофикшены стартовые скрипты и конфигурация окружения
- Устранены блокеры авторизации (частично — зависимость от litellm model pricing)

### Known Issues
- Авторизация через `POST /api/auth/login` блокируется из-за映射 модели `ministral-3b-latest` в litellm — требует настройки ценников
- Некоторые эндпоинты требуют доработки под конкретные нужды проекта
- Dev-модель `qwen2.5:3b` может давать некачественные русскоязычные ответы (ожидаемо для CPU-режима)
