## Повод

Ответ `data/pqa/answers/2b/…json`: пять источников, а в тексте ссылки
«(степень 1, степень 2)», «(степень 7)», и утверждение, что Екатерина II была
дочерью Петра I и супругой Александра I. В документах нет ни «Наполеона», ни
«Александра I» — модель достраивала факты из памяти и приклеивала
несуществующие метки цитат. PaperQA валидирует только **ключи** цитат
(`pqac-…`), истинность утверждений не проверяет никогда.

Пять пунктов, выполненных в фазе: ужесточить промпт, проверять ответ
постфактум, сузить генерацию, убрать двойное искажение сводок, завести эталон.

## 1. Правила в промпте

`RU_RULE` / `EN_RULE` (system-промпт) получили **FACT REQUIREMENT**: факты
только из контекста, из памяти ничего не добавлять, при нехватке материала —
точный отказ `I cannot answer`.

`build_qa_prompt()` заменяет в дефолтном qa-промпте sentence
*«Write in the style of a scientific article…»* на **GROUNDING RULES** —
короткий ответ без вводных и выводов, только факты из контекста, явный отказ.
Замена сохраняет шаблонные переменные (проверяется тестом через валидатор
paperqa), а если апстрим изменит дефолт — правила вставляются перед
`Answer ({answer_length}):`, чтобы модель их точно увидела. Переопределение
целиком — `PROMPTS_QA=` в `.env`.

## 2. Проверка постфактум (`grounding.py`)

Из ответа извлекаются сущности (именованные последовательности, годы, числа ≥ 2
разрядов), каждая сверяется с найденными фрагментами: точное вхождение либо
совпадение основ слов (≥ 4 букв — терпит склонения). Цифры и римские разряды
требуют точного токена: именно «1773» вместо «1772» и «Пётр I» модель и
выдумывает.

Границы честно оговорены: проверка показывает **отсутствие опоры в выдаче**,
а не доказывает ложь. Реальный дефектный ответ она ловит точно: неподтверждёнными
выходят ровно `Петра I`, `Александра I`, `Наполеон` (проверено на файлах из
`data/` — тест `test_real_defective_answer_is_caught`).

Итоговый пайплайн в `rag_service.py`:

1. `repair_markers()` — «(степень 7)» при пяти источниках удаляется, остальное
   становится `[n]`; то же для имён фрагментов paperqa «(docname lines 47-77)»
   (резолвятся в номер источника, неизвестный документ — удаляется); отчёт в
   `stats["citations"]`; старые записи кэша чинятся уже при чтении;
   дополнительно (точечные доработки фазы):

   * запись блока `References`, где **ни одна** ссылка не разрешилась,
     удаляется **целиком** — вместо строки «2.: выдумка» остаётся пустота,
     а «References» без единой записи уходит вместе с последней записью;
   * имя фрагмента **без скобок** («…см. doc lines 47-77…») переписывается
     в `[n]`, только если документ однозначно опознан; чужое имя в прозе
     не трогается (это может быть не цитата);
   * список `references` в API собирается в формате `📁 [n] название
     (категория)` — включая чтение из кэша: без номера `[n]` список нельзя
     сопоставить с цитатами в тексте ответа;
2. `_apply_refusal()` — `I cannot answer` показывается по-русски
   («Нет источника, нет утверждения») и помечает ответ неуспешным;
3. `check_grounding()` — отчёт в `stats["grounding"]`;
4. всё вместе кладётся в `FusionResult.checks`, в кэш ответа и в
   `messages.checks` — предупреждения видны и после перезагрузки.

## 3. Узкая генерация

* `ANSWER_MAX_SOURCES`: 5 → **8** (больше опор — меньше соблазна достраивать);
* `ANSWER_LENGTH`: **«no more than 120 words»** — развёрнутый текст слабая
  модель «дорисовывает»;
* `answer.evidence_skip_summary` по умолчанию `false`, флаг оповещает
  `validate_runtime()`.

## 4. Сводки: убрать двойное искажение

Сводки чанков считает та же LLM, что и ответ, — слабая модель искажает на
двух шагах сразу. Рекомендация: в `.env` задать отдельную
`SUMMARY_LLM_MODEL` (пояснения в `.env.example`). Флаг
`EVIDENCE_SKIP_SUMMARY=true` передаёт в контекст сырой текст, но замер
`SPICE_REPORT` показал обратный эффект (ответ 817 с из-за prefill) — поэтому
флаг оставлен **выключенным** и включается только осознанно.

## 5. Эталон и метрики

```
backend/scripts/eval/dataset.json   # 28 вопросов по трём документам
backend/scripts/eval/docs/          # сами документы (датасет самодостаточен)
backend/app/services/evalset.py     # check_case() / summarize() — без LLM
backend/scripts/eval_grounding.py   # прогон + метрики + пороги для CI
```

Метрики:

* `context_hit_rate` — эталонный факт найден в выдаче (поиск);
* `answer_support_rate` — обязательные факты попали в ответ (генерация);
* `forbidden_rate` — в ответе утверждение, которого нет ни в одном документе;
* `grounded_ratio` — средняя доля сущностей ответа с опорой на контекст.

Запуск:

```bash
# офлайн и быстро: только поиск (годится для CI)
.venv/Scripts/python backend/scripts/eval_grounding.py --retrieval-only

# полный цикл: поиск + ответ LLM + все метрики (нужен Ollama, минуты на кейс)
.venv/Scripts/python backend/scripts/eval_grounding.py --limit 3 --json report.json

# пороги: ненулевой код выхода, если качество упало
.venv/Scripts/python backend/scripts/eval_grounding.py --retrieval-only \
    --min-context-hit 0.9 --min-grounded 0.8
```

Честность датасета закреплена тестами: каждый «ожидаемый факт» обязан
реально присутствовать в документах, иначе метрика врала бы.

**Первый прогон дал `context_hit_rate = 0.929`** — и это оказалось не
проблемой поиска (см. следующий раздел).

## Бонус: кириллица в индексе читалась как «Р‘РёРѕРјР°ССЃР°»

Эталон сразу поймал два провала (`bm-03`, `bm-05`): ожидаемые «ацетоне» и
«батернет» не находились, хотя лежат в 750-байтовом документе. Причина — в
`paperqa.readers.parse_text()`: файл открывается **без кодировки**, то есть
в `locale.getpreferredencoding(False)`. На Windows это cp1251, а UTF-8-байты
русского текста в cp1251 валидны — исключения нет, и в индекс попадает
mojibake. Файлы, где байты всё же ломали cp1251, уходили в utf-8-фолбэк и
читались нормально, поэтому баг выглядел как «иногда портит документы».

Починка: `app/services/pqa_readers.py` — `parse_text_utf8()` (та же логика
paperqa, но с явным UTF-8), подменяется в `paperqa.readers` при импорте
`paperqa_service` (идемпотентно, одна точка). После починки эталон даёт
**`context_hit_rate = 1.0` (28/28)**.

Важно: документы, проиндексированные **до** починки на Windows, нужно
переиндексировать (`make reindex` или загрузить заново) — кракозябры уже
лежат в базе.
