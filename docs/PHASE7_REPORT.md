## Контракт цитат — ядро фазы

ТЗ требует, чтобы **каждая цифра `[n]` разрешалась в источник**. Реализовано
как проверяемый инвариант, а не как пожелание в промпте:

1. источники нумеруются `1..N` на выходе rerank (Фаза 6);
2. в промпте жёсткие правила: «не выдумывай источники», «ссылайся только на
   список», «нет факта в источниках — не пиши»;
3. `validate_citations()` проверяет результат: висячая ссылка `[9]` при
   источниках 1–2 → `ok=False` + предупреждение;
4. предупреждения собираются в `GenerationResult.warnings` **автоматически** из
   `citation_check`, а не вручную в сервисе — иначе инвариант держался бы
   только на одном пути кода.

Нумерация своя, не PaperQA: промпт собираем сами, потому что у PaperQA своя
нумерация источников и его промпт не гарантирует наш контракт.

## Генерация раздела

```
retrieve() из Фазы 6 (источники без генерации)
  -> build_prompt(раздел, вопрос, источники)   жёсткие правила цитирования
  -> PaperQA2Service.complete(prompt)          одна модель с чатом
  -> validate_citations()                      контракт
  -> ProjectVersion                            снапшот + запись в план
```

Добавлен `PaperQA2Service.complete()` — единая точка вызова LLM. Раньше
генератор разделов строил модель сам из настроек и **обходил подмену модели в
тестах**; теперь он говорит с той же моделью, что и поиск.

Режим подбора контекста: `project_focus` при статусе `drafting`/`reviewing`,
иначе `hybrid`.

## Версионирование

Каждая генерация — снапшот в `project_versions`: текст, карта цитат,
статистика, кто сгенерировал. Черновик не теряется при перегенерации, есть
`GET .../versions/diff?left=&right=` (построчный unified diff).

Кэш генераций: тот же раздел + тот же вопрос → отдаём прошлую версию, не
тратя LLM. Ключ хранится в `stats.question`.

| Формат | Что внутри |
| --- | --- |
| `markdown` | статья + список литературы |
| `docx` | OOXML через `python-docx`, Times New Roman 12, заголовки 1/2/3 |
| `zip` | `.md` + `.docx` + `references.bib` + `references/` с исходниками |

В DOCX маркеры `[n]` убраны из текста разделов (иначе Word покажет сырые
скобки) и вынесены в нумерованный список `References`. Неразрешённые ссылки
помечены явно («источник [N] не определён»), а не превращены в правдоподобный
«источник 3».

## Остаток фазы — закрыт 2026-10-02

Добавлено пять видов генерации, диспетчеризуемых по `GenerationKind`:

| Вид | Что делает |
| --- | --- |
| `literature_review` | Обзор: группировка источников по темам, отметка противоречий и нерешённых вопросов |
| `data_comparison` | Сверка своих данных с литературой: сводка CSV считается **программно**, модель только трактует |
| `gap_analysis` | Пробелы в литературе: что покрыто найденным и чего не хватает |
| `draft_analysis` | Детерминированный разбор черновика + комментарий модели |
| `report` | Отчёт по конфигурируемому markdown-шаблону (по умолчанию — HELCOM-подобный) |

### Почему числа считает код, а не модель

`data_extract.py` читает CSV/TSV (включая русский разделитель `;` и запятую
как десятичную) и отдаёт `n / min / max / среднее` по каждой числовой колонке.
LLM не умеет считать по сырому CSV, а подставлять свои числа опасно: в отчёте
появились бы выдуманные результаты. В промпте это запрещено явно («не
пересчитывай и не выдумывай»), а если сравнивать нечего — модель должна
сказать об этом прямо.

### Пробелы в черновике ищутся правилами

Поиск пробелов **детерминирован** — иначе результат нельзя проверить тестом:

* обязательный раздел без текста → `missing_section` (critical);
* утверждение с числом или силовым словом («обнаружен», «значительно») без
  ссылки `[n]` → `uncited_number` / `weak_claim`;
* результаты описаны, но методики нет → `weak_claim` (critical).

Найденное отдаётся отдельным эндпоинтом `GET .../draft-analysis` **без вызова
LLM** — быстро и воспроизводимо; `kind=draft_analysis` дополнительно просит
модель прокомментировать найденное.

## Проверено отдельно: ссылки на уровне предложения

Проверка идёт по **предложению**, а не по абзацу. На строке
«Значения существенно ниже литературных [2]. Хлорофилл 1,85 мг/м3.» первое
предложение с цитатой пробелом не считается, а второе (число без ссылки)
считается — ровно то поведение, которое нужно. Проверено вручную на этом тексте.

## Ограничения

* Шаблон отчёта приходит в запросе (`template_md`); хранения шаблонов в БД
  нет — для повторного использования клиент должен передавать его снова.
* `data_comparison` берёт документы с ролью `data`; числовые колонки определяются
  автоматически, выборочно задать тип колонки нельзя.
* Все виды генерации, кроме `draft_analysis` и `gap_analysis`, требуют LLM —
  на dev-машине это минуты, как и положено по условию задачи.
